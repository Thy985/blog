# 本体逆向：用 Ghidra 读 Go 二进制

> 上游逆向在源码层面完成，但 fork 新增的行为细节在源码注释里不完整。
> 需要从二进制里验证——这一条线叫"本体逆向"。

---

## 1. 为什么还要分析二进制

一个项目从上游 fork 后，新增了大量行为：面板、错误分类细化、任务体系等。这些**新增行为的细节在源码注释里不完整**，甚至可能与线上二进制不一致。

所以需要本体逆向：直接分析线上二进制（一个 stripped 的 Go 可执行文件），验证源码断言，补全未文档化的细节。

## 2. 分析流程

用 Ghidra（开源反编译器）对一个 Go 二进制做完整分析，流程分五步：

```
Step 1: 环境准备
  ├─ 安装 Ghidra
  ├─ 设 GHIDRA_INSTALL_DIR
  └─ 验证环境（doctor 检查 7 项全 ok）

Step 2: 导入分析
  ├─ analyzeHeadless 导入二进制
  ├─ 约 6 分钟完成
  └─ 产出：8624 个函数（Go 二进制通常偏大）

Step 3: 导出目标函数
  ├─ 用 Ghidra 脚本按包分组导出 C 伪代码
  └─ 产出 decomp/*.txt

Step 4: 逐函数解读
  ├─ Classify（错误分类）→ 14 路决策树
  ├─ pickWeighted（选号）→ 加权轮盘赌
  ├─ hasBusinessEnvelope（响应解析）→ 锚点串
  └─ ResolveModel（模型解析）→ 双域路由

Step 5: 全局量恢复
  ├─ _lists.txt: 关键词名单（39 条字面量）
  ├─ _globals.txt: 锚点串、时区、正则
  └─ 交叉验证反编译产物 + 源码
```

## 3. Go 二进制的特殊之处

Go 编译的二进制有几个特点影响逆向：

### 3.1 stripped 但符号可恢复

Go 二进制默认 stripped（去符号表），但 Go 的**类型信息、函数名、包结构**在二进制里有特殊编码。用 **GoReSym** 这类工具可以恢复大部分符号——函数名、包路径、类型信息都能还原。

### 3.2 BSS 全局量运行时初始化

很多常量（如权重缩放常量）**在编译期是 0**，运行时才初始化。所以反编译时看到的全局量值未必是真实值——需要结合运行时上下文判断。

> **教训**：Go 二进制逆向不能全信反编译器的字面量输出。`DAT_xxxx` 这类符号的反编译值，要么交叉验证，要么标 `// TODO: unknown`。

### 3.3 锚点串定位函数

Go 字符串字面量集中在 rodata 段，反编译时可以作为**定位函数的锚点**：

- `"code":` 和 `"msg":` 这对锚点串定位响应解析函数
- 错误关键词名单定位错误分类函数

## 4. 关键发现

本体逆向最有价值的几个发现：

### 4.1 14 路 Classify 决策树

错误分类的完整决策树——源码里只有简化版，反编译拿到了**完整优先级链**。这补全了源码注释里缺失的"先于谁"顺序。

### 4.2 39 条关键词名单

上游所有错误文案的汇总——源码里是**空数组**（运行时从别处填充），反编译从 rodata 提取到了完整的 39 条字面量。

> **教训**：源码里的"空数组"未必意味着"没有数据"——数据可能从二进制资源段、配置、或外部填充。逆向要看二进制里的真实数据，不能只看源码声明。

### 4.3 加权选号完整算法

`pickWeighted` 的完整算法——`float64 权重 × 缩放常量 → 累加 → randInt64N(total)` 做加权随机。源码里只有部分，反编译拿到了缩放常量的真实值。

### 4.4 一个惊人的不一致：拼写错误

反编译发现线上二进制里有一个字段的值是 `"develope"`（少一个 `r`），但 GitHub 源码用的是 `"developer"`。

**线上二进制和 GitHub 源码不一致。**

> **教训**：源码和线上二进制可能有出入。任何基于源码的逆向结论，如果想确认线上行为，必须从二进制验证一遍。

## 6. 方法论价值

本体逆向对方法论的价值：

### 6.1 逆向审计

"关键断言 ↔ 代码出处"对照表是**逆向审计的产物**——它让每个行为断言可追溯，既到源码、也到二进制。这是逆向工程"可复现、可验证"的体现。

### 6.2 源码不是终审

源码可能滞后于线上二进制。**线上行为 = 二进制行为**，不是源码行为。任何对线上行为的断言，最终要以二进制为准。

### 6.3 GoReSym + Ghidra 的组合

Go 二进制逆向的标配工具链：

| 阶段 | 工具 |
|---|---|
| 符号恢复 | GoReSym |
| 反编译 | Ghidra / IDA / Hopper |
| 动态调试 | Delve |
| 协议测试 | curl / 自写客户端 |

## 7. 小结

本体逆向不是"上游逆向"的重复——它验证、补全、纠错。没有这一步，你对项目的理解停在"源码层"，而线上行为在"二进制层"。

> **协议是公开的，行为模型不是——而行为模型的最终事实源是二进制，不是源码。**
