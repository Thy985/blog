# 账号池调度：从加权选号到会话粘性

> 账号不是等价资源，而是有余额、到期时间、历史成本、实时健康度的资产。
> 选号 = 在多目标（省积分、避免浪费快过期批次、均衡负载、避开风控）间做软偏好折中。

---

## 1. 为什么需要账号池

单账号网关的瓶颈很直接：**一个号限流了，整个网关就不可用**。

多账号池的核心价值是**故障转移与流量治理**：

- 单号故障自动换号
- 冷却 / 熔断防止雪崩
- 会话粘性保证多轮上下文不跳号
- 按余额 / 成本 / 健康度做调度

## 2. 选号算法：加权轮盘 + 分层过滤

多账号调度的核心是**加权轮盘赌 + 分层过滤**：

```
1. 过滤：跳过已试过的、冷却中的、积分触底的、在途占满的
2. 候选集按权重排序，取 Top5
3. Top5 内按权重做轮盘赌随机抽签
4. 无健康候选 → 全冷却兜底，选最早解冻的账号
```

### 2.1 权重公式

权重 = 基础权重 × 各因子：

```
w = 1.0
if 冷却中      { w *= 0.1 }    // 冷却中的几乎不选
if token 过期  { w *= 0.01 }   // 过期的几乎不选
if 历史成本>0  { w *= 0.5 }    // 实测收费的降权
```

业务层再叠加：

- **积分比例 × 10**：余额越充足的号权重越高
- **闲置时间加权**：`min(闲置小时 × 0.5, 5.0)`，闲置越久权重越高
- **快过期积分加权**：168 小时内有效批次将到期的号权重 ×3（软偏好，弱于会话粘性与成本分层）

### 2.2 为什么用 Top5 短名单

**不是所有候选都参与抽签**——先取权重最高的 5 个，再在 5 个内加权随机。

> **意图**：打散热点，避免永远打同一个账号。纯均匀随机太散（缓存、粘性全废），纯最高权重又太集中（热点账号超限）。Top5 是两者之间的折中。

### 2.3 防惊群

跳过 **100ms 内刚被选中**的账号——防止多个并发请求在瞬间全部选中同一个"最优"账号。

### 2.4 全冷却兜底

无健康候选时，从非禁用账号中选**最早到期者**顶班——宁可让请求发出，也不因"全池冷却"直接 503（除非是积分触底保护，见下）。

## 3. 按模型实测成本分层

账号不是平等的，**模型也不是**。网关按实测成本把账号分三层：

```
tier 0：实测免费的模型（用这个模型的账号不消耗积分）
tier 1：无观测数据的模型
tier 2：实测收费的模型（消耗积分）
```

**选号只保留当前最优层**：请求用免费模型时，只在 tier 0 账号里选；请求用收费模型时，才考虑 tier 2。

## 4. 积分保底：宁肯 503 也不放行

`credit_floor`（默认 100）是一道**保护线**：

- 余额低于该值时，对收费模型不再参与选号
- 防止收费模型把最后一个号的余额打穿
- 全池触底且全 tier 2 时 → 返回空 → 网关 503，**不放行**

> **设计哲学**：**宁肯 503 也不放行**。因为"放行"意味着把最后一个号的余额打穿、连免费模型都不可用 11.5 小时（硬冷却到次日）。503 是一时的，打穿是长久的。

## 5. 成本探索：搭车改道

`cost_explore_interval`（30 分钟）解决一个困境：免费层垄断且存在未知账号时，怎么知道某个号是免费的还是收费的？

> **做法**：把真实请求"搭车"改道给未知号（零新增上游请求），成功即确认该号免费，毕业进 tier 0。

这是**用真实流量做在线实验**——不额外打上游，只是把已经要发的请求改道，从结果学。

## 6. 会话粘性：多轮上下文不跳号

多轮对话要求同一会话始终走同一账号，否则**上下文断裂**。

### 6.1 会话键提取顺序

```
metadata.conversation_id → metadata.conversationId → metadata.user_id
  → 顶层 conversation_id → 顶层 conversationId（snake 优先 camel）
```

### 6.2 无 ID 时的内容派生键

客户端不发会话 ID 时，用 `system + 首条 user` 哈希派生一个 `d-` 前缀的键——**通用 OpenAI 客户端也能享受粘性**。

### 6.3 生命周期

- TTL 30 分钟滚动续期，GC 5 分钟
- 可镜像到外部 Redis（7 天 TTL）防重启丢失
- 失败自动解绑
- 绑定号被模型级限流后，换模型请求自动解绑重分配

## 7. 定时任务生态：把"逆向"延伸到"账号资产经营"

账号池不仅是转发流量，还可以**经营账号资产**——这是多账号网关与通用网关最本质的差异：

| 任务 | 作用 |
|---|---|
| 签到 | 每天领积分回血 |
| 活跃上报 | 解锁某些功能的前置 |
| token 保活 | 防止 token 过期 |
| 连登管家 | 连续登录档位兑换 |
| 旅行 / 夜猫子 | 周期性活动收益 |
| 余额刷新 | 定时刷新账号余额快照（5 分钟） |

> **关键设计**：**恢复动作本身就是业务**。签到不只是"养号"，它是积分耗尽账号唯一的自动回血路径。所以"禁用账号也参与签到"这个开关才有存在意义——否则待命号拿不到积分，一次放开一个号时越用越亏。

## 8. 一句话总结

> **多账号调度 = 把账号当资产经营：余额、到期时间、历史成本、实时健康度，全部塞进权重函数；冷却体系按"账号问题 vs 请求问题"分流；任务生态让每个号自己回血。**

账号池的代码是**运营真实多号才写得出的代码**——它把"运维经验"编译成了调度规则。下一篇换一条线：**本体逆向**——用 Ghidra 读 Go 二进制。
