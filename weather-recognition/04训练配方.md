# 训练配方——从损失函数到早停

> 系类第4篇：把“怎么学”写出可复现的清单，而不是调参故事

### TL；DR

第3篇讲的是“模型看到什么”，这一篇讲“模型怎么学”。训练配方的每一个组件——损失函数、优化器、学习率与调度、早停、混合精度、随机种子——都在和**小样本+类别不平衡+分布偏移**这三重约束对话。核心结论只有一条：**小样本迁移学习场景下，配方的目标是“稳定找到泛化点”，而不是“在训练集上拟合到最好**。早停和验证集纪律，比任何单一超参数都更早决定成败。

## 1.问题背景：为啥训练配方值得单独写

第1篇定义了约束：约4990张训练图，1.75:1不平衡，隐藏测试集存在分布偏移。第2篇选了模型：ImageNet预训练ResNet.第3篇讨论了增强：合成噪声是最大的单项提升，Mixup/CutMix失效。

但增强只解决”输入长什么样“。模型拿到输入之后，**损失函数怎么算、参数怎么更新、什么时候停下来**，是另外一套独立的决策。这套决策如果写不清楚，实验就无法复现，结论也无法归因——一个提升到底来自增强、模型，还是学习率碰巧合适？

这一篇的目标是把训练配方写成**可复现的清单**：每个组件回答一个具体问题，每个选择对应一个项目约束，每个”有效“或”无效“都有证据来源

## 2.损失函数：交叉熵与不平衡处理

### 2.1标准交叉熵为啥不够

交叉熵是分类任务的标准损失。但在1.75:1的类别不平衡下，标准交叉熵仍有一个已知的倾向：**模型偏向多数类**.多模态的样本数量多，对总损失贡献大，模型把多数类分对就能捕获不错的平均损失，少数的错误被”平均掉“了。

这就是第1篇强调Macro-F1的原因——Accuracy和标准交叉熵的优化方向，并不天然对齐Macro-F1.

### 2.2常见的修正手段及其代价

| 方法       | 做法                         | 代价                               |
| ---------- | ---------------------------- | ---------------------------------- |
| 类别权重   | 少说类的损失乘以更大的系数   | 可能过度校正，改变有效分布         |
| 加权采样   | 少数类被采到的概率更高       | 同上；小样本重复采样               |
| Focal Loss | 对易分类样本降权，聚焦难样本 | 在极端不平衡有效，但引入额外超参数 |
| 标签平滑   | 把硬标签软化                 | 在小样本+噪声标签下常用            |

项目里的实际结果是：**加权采样和类别权重没有带来正向收益**。一个合理的推断是：不平衡不是主要矛盾，**分类偏移才是**。在训练集上强制纠正类别先验，可能让模型对训练集的分布过度校正，而平台测试集的先验未必一致。

### 3.2 在迁移学习、微调场景下，证据怎么说

一项系统性的微调发现:**在新的架构（Vit、ConvNeXt)上，AdamW明显优于SGD,尤其是在分布外**（OOD）**准确率上**——7 个模型、5 个数据集的平均 OOD 准确率为 76.0% vs 72.0%。但对于**较老的ResNet架构(BiT ResNet-50/101),AdamW和SGD的性能**没有明显差异。所以这个项目选择什么优化器，本质上 差别不大。

不过有研究指出：**自适应优化器(如AdamW)在数据有限时可能过拟合于虚假的梯度统计量**。在小样本场景下，这不是一个可以忽略的风险。

### 3.3关于优化器选型

**本项目没有对AdamW与SGD进行过系统的对照清单。**

这是一个明确的局限，因此这里无法用自身证据来论证“为啥选择这个优化器”。

## 4.学习率与分层策略：保护底层，放开顶层

### 4.1为什么迁移学习需要分层学习率

ResNet的底层时边缘、纹理等**通用特征**，这些特征在ImageNet和天气分类之间时共享的，不应该被大幅改动。顶层（尤其时分类头）时**任务特定**的，需要快速适应新类别。

统一学习率的问题在于：它要么太大，把顶层的有用特征冲掉；要么太小，让分类头学得太慢。**分层学习率**就是为不同层组设置不同的学习率来解决这个矛盾。

### 4.2常见的分层方式

| 层组                   | 推荐学习率 | 理由                         |
| ---------------------- | ---------- | ---------------------------- |
| **预训练主干（浅层）** | 较小       | 保护通用特征，避免灾难性遗忘 |
| **预训练主干（深层）** | 中等       | 允许一定程度的任务适配       |
| **新分类头**           | 较大       | 从随机初始化快速学习         |

当新数据集与训练集数据**相似**时，顶层学习率可以设为底层的约10倍；差异较大时，可以进一步放大这个比例。对于ResNet-50这类更深的网络，深层卷积层有时需要**极低的学习率**(如1e-5)来保留预训练特征，而分类头侧需要较高的学习率(如1e-3)

### 4.3渐进式解冻：更保守的替代方案

如果不确定分层学习率的比例，另一个策略是**渐进式解冻**：先冻结全部主干，只训练分类头；然后逐层解冻，或者解冻最后几个stage,同时降低学习率。这种方法在小样本下更保守，但训练时间更长，且需要决定“什么时候解冻多少”。

**项目关联**：这个项目使用的是标准ResNet,分层学习率是一个**合理但未被充分验证**的选型。

## 5.学习率调度：让学习率随时间变化

### 5.1常用的调度器

| 调度器           | 行为                          | 适用场景                                   |
| ---------------- | ----------------------------- | ------------------------------------------ |
| step Decay       | 每隔固定epoch乘以一个衰减因子 | 简单、可预测                               |
| Cosine Annealing | 学习率按余弦曲线平滑下降      | 训练后期精细收敛，小样本常用               |
| Warmup+衰减      | 先线性升温，再衰减            | 稳定训练初期，防止早期大部长破坏预训练特征 |

### 5.2小样本的调度选择

**这个在项目中是一个被早停掩盖的问题**

项目没有对学习率调度器做过系统对照,无法回答哪个调度器更好。

**虽然配置了学习率衰减策略，但由于训练过早结束，该策略可能根本没来得及执行；而由于缺乏关键日志，后期我复盘的时候无法验证这一猜测，导致模型性能不佳的原因变得模糊不清。**其实这个问题在小样本迁移学习中很常见：

- **数据量小，收敛快，早停触发时间窗口非常早**
- **迁移学习的特性，可能复用预训练大的Epoch配置**

无论怎么样，这个项目无法回答调度选择的问题

## 6.早停：训练配方里最重要的“停止信号”

### 6.1早停的逻辑

早停监控验证集上的某个指标。如果这个指标在连续patience个epoch内没有改善，就停止训练，并**回滚到验证集上表现最好的那个checkpoint**，而不是最后一个epoch模型。

这个“回滚”动作是早停最重要的价值：它不改变训练过程，但它**改变了你拿到的模型**。最后几个epoch的模型可能已经在过拟合训练集，验证集指标下降；早停把模型选择权从“训练结束时刻”转移到“验证集最佳时刻”。

### 6.2patience怎么设

在小样本微调场景中，常见的patience取值是**5到10**个epoch.更小的patience可能过早停止，错过验证集指标的一次短暂低谷后的回升；更大的patience会浪费训练时间，并且在分布偏移场景下可能让模型在“本地验证集的最佳点”停留过久。

但patiecne本身不是孤立的。一项针对小数据集的实践建议是：**先开基础配置——权重衰减、验证集监控、必要时提取停止；如果仍然过拟合，再加数据增强；再不行，才考虑Dropout、标签平滑或缩小模型**。这个顺序背后的逻辑是：早停和验证集纪律是**成本最低、最先应该到位**的正则化，而不是最后才想起来的手段。

## 7.混合精度训练：速度、显存与稳定性

### 7.1AMP在做什么

自动混合精度（AMP)把一部分运算（如矩阵乘法、卷积）放到FP16/BF16中执行，同时保留FP32的权重主副本和关键累加操作。这样做的收益是**显存减半、训练速度提升2-3倍**（取决于硬件和张量核心利用率）。在ResNet-50级别的模型上,AMP的加速比可以到达1.5-2.9倍

### 7.2在小样本中的实际意义

小样本训练的总计算量不大，AMP的“加速”收益不像大模型预设训练那么显著。但显存收益是实打实的：更低显存占用允许更大的batch size,或者在同一张GPU上跑更多并行实验。

## 8.随机种子与可复现性:配方的一部分

### 8.1为什么种子属于训练配方

如果只固定模型和超参数，不固定种子，两次训练的结果可能不同。在小样本场景下，**数据划分的随机性**和**参数初始化的随机性**会被放大——一个不同的随机划分可能让本地验证集指标波动几个百分点，足以让“有效/无效”的判断翻转。

可复现标准做法是：在项目的配置文件统一设置python的random,numpy,pytorch的种子；在可行的情况下启用torch.use_determinstic_algorithems(True)和cuDNN的确定性模式。同时，DataLoader的shuffle序列也应通过torch.Generator固定，否则每次epoch的样本顺序不同。

```
1. torch.use_deterministic_algorithms(True)：
是 PyTorch 提供的一个全局开关。默认情况下，PyTorch 为了速度，可能会为某些操作（如矩阵乘法、卷积、散点加法 scatter_add等 multiple implementations）选择最快的但非确定性的算法。

2. CuDNN 的确定性模式：
是 NVIDIA 提供的深度学习加速库。对于卷积（Convolution）和池化（Pooling等常见操作，CuDNN 内部有多种算法可选（如 convolution_algo）。默认情况下，CuDNN 会根据输入张量的大小自动 benchmark 并选择最快的算法，其中一些快速算法是非确定性的。

3. DataLoader 的 shuffle 序列通过 torch.Generator 固定：
在训练每个 Epoch 开始时，我们通常会打乱（Shuffle）数据集，以防止模型记住样本顺序。默认情况下，Python 的 random 模块或 NumPy 的随机状态可能不受 PyTorch种子控制，或者在多进程 DataLoader 中，子进程的随机状态难以同步。
```

### 8.2确定性的代价

完全确定性通常会**降低训练速度**，因为一些非确定性的算子被替换成了确定性但更慢的实现。在小样本、短训练的场景下，这个代价通常可以接受。

在项目中：

- **在数据层面，种子是固定的**。seed=42控制训练/验证划分、所有数据增强和噪声增强的随机序列，以及DataLoder的随机顺序。划分索引通过torch.randperm(n_total,generator=torch.Generator().manual_seed(SEED))生成，同一SEED比如得到同一划分。config.py中NUM_WORKERS=0(Windows兼容性约束)，因此多进程DataLoader的work种子问题在当前配置下不适用；但如果未来为了加速启用多worker,需要引入worker_init_fn来固定每个worker的随机状态
- **在GPU算子层面，项目主动放弃了完全确定性**。seed.md记录了标准配置——torch.backends.cuddn.deterministic=True、benchmark=False.

## 9.完整配方清单

把所有组件串起来，一个**可复现的小样本迁移学习训练配方**至少应该包含以下字段：

| 组件           | 内容                                                  | 项目约束                                                    |
| :------------- | :---------------------------------------------------- | :---------------------------------------------------------- |
| **损失函数**   | 标准 CE / 加权 CE / Focal / 标签平滑                  | 1.75:1 不平衡；项目加权采样/类别权重无正向收益              |
| **优化器**     | AdamW / SGD / 其他；weight decay 值                   | 小样本下自适应优化器的过拟合风险；ResNet 上两者差异可能不大 |
| **分层学习率** | 是否启用；主干 lr 与分类头 lr 的比例                  | 保护预训练通用特征，加速分类头适配                          |
| **调度器**     | 类型、总 epoch、warmup 设置                           | 与早停触发时机匹配，避免“调度未完成就停止”                  |
| **早停**       | 监控指标（验证 loss 或 Macro-F1）、patience、回滚逻辑 | 本地验证 ≠ 平台，早停选出的最佳点需要平台信号验证           |
| **Batch size** | 实际值；是否受显存限制                                | BN 在小 batch 下的统计量稳定性（第 2 篇）                   |
| **混合精度**   | 是否启用 AMP；FP16 还是 BF16                          | 工程效率选项，不是精度提升手段                              |
| **随机种子**   | 统一 seed；DataLoader Generator；确定性开关           | 小样本下划分和初始化的方差放大效应                          |
| **训练时长**   | 冠军单模型约 30 分钟（RTX 3060 级别）                 | 工程约束的一部分，影响实验迭代速度                          |

## 12.可迁移结论

- 小样本迁移学习的默认顺序：**早停+验证集纪律->基础正则化->分层学习率->再考虑损失工程和复杂调度**
- 优化器选择要看架构和数据规模，不要默认AdamW一定更好
- 分层学习率的原则是“底层小、顶层大”，比例可以从 10× 起步，根据数据与预训练分布的相似度调整。
- 早停的 patience 设 5–10 是常见起点；但更重要的是**记录早停触发点**，并和平台信号对照。
- AMP 是速度和显存手段，不是精度手段；如果追求可复现性，确定性开关是有代价的，需要权衡。
- 随机种子和 DataLoader shuffle 固定，是配方可复现的最低要求。
