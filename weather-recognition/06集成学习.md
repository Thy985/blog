# 集成学习——系统差异比伙伴强度更重要

> 系类第6篇：为什么本地更强的模型，反而可能拖垮集成

### TL；DR

项目里有一个持续出现的悖论：在本地验证集上，ResNet18的单模型F1(0.923)高于ResNet50(0.891)；但加入集成后，更强的ResNet18导致集成崩溃(-0.012)，更弱的ResNet50反而帮助了集成(+0.006).同模型的Yule'sQ 高达0.9560,意味着它们的错误高度相关；而ResNet 50与F1配方的预测分歧率最高（0.0741），提供了RN18无法提供的互补错误模式。伙伴价值排序与分歧率排序一致，与单模型精度排序相反。这一篇把“系统差异”从一个直觉变成一个可度量的选择标准，并讨论它在什么条件下成立，什么条件下失效。

## 1.问题背景：一个让本地指标失效的悖论

第5篇讲了四次“本地升、平台降”。其中集成伙伴的反转最反直觉：

| 模型     | 本地单模型F1 | 集成贡献 |
| -------- | ------------ | -------- |
| ReNet18  | 0.923        | -0.012   |
| ResNet50 | 0.891        | +0.006   |

如果“集成就是让好模型投票”，那么更强的模型应该带来更大的增益，或者至少不应该拖垮集成。但数据说相反。

这一篇要回答三个问题：

1.“系统差异”到底指什么？它能不能被度量？

2.为什么本地单模型强度不能预测集成贡献？

3.“多样性优先”有没有边界？在什么条件下它会失效？

---

## 2.知识地图：多样性不是“感觉不同”，而是一组可计算的量

### 2.1集成收益从哪里来

经典集成理论的目标是降低误差。如果成员模型的错误**完全独立**，集成可以通过平均把方差压下去；如果成员的错误**完全相关**，集成就只是把一个模型复制多份，增益趋近于0

所以集成的核心变量不是”每个成员有多强“，而是**成员之间的错误在多大程度上是独立的**。这是“多样性"的严格含义

### 2.2常用的多样性度量

文献常用的成对多样性度量包括：

| 度量         | 含义                                 | 方向             |
| ------------ | ------------------------------------ | ---------------- |
| 分歧率       | 两个分类器预测不同的样本比例         | 越高越多样       |
| Yule's Q     | 两个分类器预测的关联强度，范围-1到+1 | 绝对值越低越多样 |
| Double-Fault | 两个分类器**同时出错**的样本比例     | 越低越互补       |
| 误差相关性   | 错误向量的相关系数                   | 越低越互补       |

Yule's Q 的直观含义是“两个分类器是一起对、一起错，还是各错各的”。Q 接近 +1 意味着高度关联——它们倾向于一起对或一起错；Q 接近 0 意味着预测接近独立；Q 为负意味着一个对的时候另一个倾向于错。

### 2.3一个容易被混肴的点：多样性 ≠ 准确率

多样性和单模型准确率是**两个独立的维度**。

一个模型可以很强，但和其他成员错得一样（高准确率+高错误相关性）；也可以很弱，但错得不一样。

集成要得是**在可接受准确率得前提下，错误模式尽可能不重叠**。这不是”越弱越好“，而是”弱得有价值“——较弱但错误模式互补的模型，可能比更强但错误冗余的模型贡献更大。

## 3.仓库证据：Yule's Q 0.9560和分歧率0.0741在说什么

### 3.1同族模型的错误高度相关

F1配方与E03(同族不同训练策略)之间的Yule's Q为0.9560

对照警戒线(相关性>0.075即冗余)，0.9560意味着这两个模型**几乎是一起对、一起错**的。它们之间的差异，主要是同一家族内部的细微训练差异，而不是系统性的错误模式差异。

ResNet 18虽然比ResNet 50"更强",但它与现有成员共享了高度相似的错误结构。

### 3.2ResNet50的分歧率最高

ResNet50与F1配方的预测分歧率为0.0741,是可部署模型中最高的。

它的本地单模型F1较低(0.891),意味着它在本地验证集犯过的错误比RN18多。但这些错误**落在RN18/F1配方不会出错的样本上**——它提供了集成中其他成员不具备的”不同视角“。+0.006的平台收益，正式这种互补错误模式的定价。

### 3.3排序的方向

**伙伴价值排序与分歧率排序一致，与单模型精度排序相反**。

## 4.外部证据：竞赛和深度学习研究中的同一规律

### 4.1kaggle:多样化模型，即使CV分数更低。

kaggle高排名选手在讨论stacking时给出一条非常直白的建议：

> “下一步提升 CV 和 LB 分数的建议，是**创建更多样化的模型，即使它们自身的 CV 分数较低**。因为 stacks 喜欢大量多样化的模型。”

另一条讨论则从反面确认了同一件事：**如果模型之间不够多样，简单平均集成的结果可能比最好的单模型还差**

这不是说：弱模型更好，而是说：在集成语境下，**单模型CV不是选择伙伴的正确货币。**集成关心的是错误模式的覆盖，而不是每个成员独立跑分的更低。

### 4.2深度集成研究：高多样性 = 错误的独立性

一篇 2024 年的 IEEE 会议论文在讨论深度集成时明确指出：**高多样性的成员模型，其预测错误具有更高的独立性**，这为提升整体集成性能提供了潜力。该文提出的多样性优化指标与集成准确率**和 OOD 鲁棒性**都表现出强相关，说明多样性不仅关乎平均精度，还关乎分布偏移下的稳定性。这一点与项目中“平台分布偏移”的约束直接呼应：在一个本地指标不可靠的环境里，一个依赖错误互补性的集成，比一个依赖单模型强度的集成更可能扛住分布变化。

### 4.3 一个更精确的量化：个体误差高，但多样性补偿了它

IEEE Access 2025 年的一项 AutoML 集成研究给出了一个非常贴近项目的观察：

> “BO 阶段的管道实现了更低的个体错误率，但**缺乏多样性**；而 Caruana 阶段的管道，**尽管个体错误率更高，却为集成贡献了大得多的多样性**。这种多样性**补偿了更高的个体错误率**，使 Caruana 集成实现了更优的整体错误率。”

这几乎是与项目中 RN18/RN50 反转对应：**个体更准的模型群体（低错误率、低多样性）输给了个体稍弱但更多样的模型群体。**

## 5.边界条件：“多样性优先”在什么时候会失效

我们不能无脑吹捧多样性，需要考虑边界。

### 5.1过参数化条件下的理论限制

ICML 2025的一项研究表明：**在过参数化调教下，无限集成模型与单个无穷模型逐点等价；集成方差不再反应传统的不确定性，深度集成相比大模型没有本质的泛化优势**

这讨论的是**过参数化（模型容量远远超过数据规模）条件下的极限行为**。这个项目恰好是相反的情况，是小样本的区间，多样性带来的互补错误模式仍然是集成增益的主要来源。

但这提醒我们：“**系统差异优于伙伴强度”不是一个无条件成立的定律，而是小样本、分布偏移、有限容量约束下的经验规律。**

### 5.2多样性不能弥补“太差”的成员

如果ResNet 50的本地F1不是0.891,而是0.60,它的高分歧率也不会带来正向收益。多样性有价值的前提是成员**仍然在一个可接受的性能区间内**。一个错得离谱得模型提供得是噪声，不是互补信号。

## 6. 结果与证据

| 证据              | 数值                     | 含义                                     |
| :---------------- | :----------------------- | :--------------------------------------- |
| F1 × E03 Yule's Q | **0.9560**               | 同族模型错误高度相关，冗余而非互补       |
| RN50 × F1 分歧率  | **0.0741**               | 可部署模型对中最高，提供互补错误模式     |
| RN18 本地 F1      | 0.923                    | 本地更强                                 |
| RN18 集成贡献     | **−0.012**               | 崩溃                                     |
| RN50 本地 F1      | 0.891                    | 本地较弱                                 |
| RN50 集成贡献     | **+0.006**               | 帮助                                     |
| 伙伴价值排序      | 与分歧率一致、与精度相反 | 集成选择的正确货币是分歧率，不是本地精度 |

## 7.负结果与教训

这一篇得负结果是一个**方法论的负结果**：

**”选最强的模型做集成“是一个错误的默认策略。**

教训：

1. **单模型强度和集成贡献是两个不同的量。** 不要用同一个排行榜来同时回答两个问题。
2. **同族模型的多样性可能被高估。** 换深度、换训练策略，不等于换错误模式。Yule's Q 0.9560 是量化证据。
3. **分歧率可以作为一个显式的选择信号。** 它不需要平台反馈，在本地就能计算，而且与集成贡献的排序一致。
4. **多样性优先有边界。** 不要把这个结论推广到“越弱越好”或“多样性无条件重要”。成员的可接受性能和任务 regime 都需要被纳入判断。

## 8.可迁移结论

如果你也在做小样本集成：

- **先算分歧率和错误相关性，再决定伙伴**。
- **警惕同类型模型带来的虚假多样性**
- **“把弱得有价值”和“弱得没用”分开**。
- **在大模型/过参数化场景下保持谨慎**
- **把伙伴选择写出一个可复现的筛选步骤**。计算成对分歧率/误差相关性->剔除冗余对中较弱者->在剩余候选上做权重搜索。
