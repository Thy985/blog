# 技能抽象——机器人 API 的设计学

> "移动到""抓取""放置"是三个动作，"把红色方块从 A 搬到 B"是一条指令。中间的翻译层叫技能（Skill）：带前置条件、后置条件、成本与恢复策略的可复用行为单元。这一章讲技能抽象的设计学，以及它为什么是 LLM 与机器人之间**唯一正确**的接口。

---

## 1. 技能：动作的"类型系统"

裸动作（move/grasp/place）的问题是**组合不可靠**：任意排列它们可以构造出无数非法序列（没抓就提、没到就放、超负载搬运）。技能抽象给动作加上**类型约束**：

- **前置条件（preconditions）**：什么时候可以执行（"物体在桌上、夹爪空闲"）——通常是 WorldModel 的关系查询（09 篇的 Relation 层）；
- **后置条件（postconditions）**：执行成功后世界应该是什么样（"物体 attached_to 夹爪"）——执行后可验证，验证失败即触发恢复；
- **参数与类型**：输入输出参数有 schema；
- **成本**：时间、风险、成功率——供上层（未来的 Agent/LLM）选择时权衡；
- **恢复策略**：每类失败对应什么处理。

有了这套约束，"把方块从 A 搬到 B" = `pick(A) → place(B)`，**组合的正确性由前后置条件保证，不再依赖执行者记得所有规矩**。这就是技能作为"动作类型系统"的含义。

## 2. 与两个学术传统的血缘

技能抽象在两个传统里都有严格版本：强化学习的 **options 框架**（技能 = 策略 + 终止条件 + 值函数，是"分层 RL"的基石），以及 **TAMP（任务与运动规划）**（技能 = 带符号前后置的操作符，规划器在符号层搜索动作序列）。本章不展开理论，只记一个工程结论：**技能接口是"学习派"与"确定性派"的天然总线**——学出来的策略可以包装成一个技能（precondition/postcondition 不变），手写的技能也可以被 LLM 调用（SayCan 式"LLM 打分选技能"正是用技能库当词表）。11 篇的接口设计直接决定 14 篇能接什么。

## 3. 项目实例：Skill 五要素与一次接口冻结

M6.3 的 Skill Runtime（`multi_arm_skill_runtime`）把技能做成**声明式 YAML**（`skill_manifest.py` 的自述："similar to package.json"）：

```yaml
# Skill Manifest 声明的七件事（源码 docstring）：
required_capabilities   # 需要的机器人能力
input_params/output_params
cost                    # time / risk / success_rate
preconditions           # WorldModel 关系查询
execute_steps           # 有序执行步骤
postconditions
recovery                # 失败类型 → 策略
```

配套四个组件：**Registry**（技能注册与发现）、**Lifecycle**（状态机：unloaded → loaded → active…）、**Composer**（组合技能——用小技能拼大技能，组合后重新生成 Manifest）、**bt_skill_wrapper**（技能包装成 BT 节点，与 06 篇的编排层对接）。

两条工程决策值得记住：

1. **成本三元组是给"选技能的人"看的**——`SkillCost` 的 docstring 原文："used by Agent for skill selection"。技能层从第一天就为上层 Agent/LLM 留了席位，尽管 LLM 从未接入（06 篇的"非自然语言"决策）；
2. **接口冻结（M5.7 Interface Freeze v1.0 → M6.3 SPEC 12 项冻结 + ADR）**：技能接口被显式冻结为 v1.0，冻结意味着"上层（M6.5 Runtime API、未来的 M7）可以安全依赖"。**先冻结再往上盖楼**，是分层系统能活着长到第七层的纪律前提。

**演进注记**：技能层是 M6 才出现的——M4.6 的自主任务循环里，BT 直接编排裸动作（AsyncGraspNode、AsyncPlaceNode 是 BT 叶子，不是技能调用）。"动作升级成技能"不是重写而是**包了一层**（bt_skill_wrapper 包住原有 BT/动作路径），上层编排代码几乎不动——这是"加层不拆楼"重构的一个干净样本。

## 4. 边界与不足

技能全部手写 YAML（个位数技能），没有从演示中**学习**新技能（学习派的核心承诺，13 篇）；`cost` 是声明值不是实测值（success_rate=0.95 写在 YAML 里，没有基准系统回填真实数据——M5.4 的 benchmark 本可以喂它）；precondition 查询依赖关系层的手工规则（09 篇边界）；Composer 组合后的前后置验证比较朴素；技能没有版本迁移机制（接口冻结了，但技能库自身的演化路径未定义）。

## 5. 一句话总结

> 技能 = 带类型约束的动作单元，它是动作的"库"、LLM 的"词表"、学习策略的"包装标准"。技能接口设计得好坏，直接决定这个机器人十年后能不能接上大脑。

下一篇是系列的转折点：把散落在各篇的"边界与不足"集中起来，整理成一张"确定性栈解决不了什么"的清单——它同时就是学习派的入场券。
