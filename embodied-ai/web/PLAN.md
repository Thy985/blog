# 具身智能学习站 · 前端规划

> 目标：把 `embodied-ai/` 下 21 篇文章变成一个**公开博客站**，同时满足两件事——
> **演示效果**（拿得出手的视觉与交互）和**知识传递效果**（读者真的学会了，而不是滑过去了）。
>
> 核心约束：**21 个 `.md` 文件是唯一真相源，一行不改。** 所有结构化能力由构建期解析产生。

---

## 0. 内容资产盘点（决定了前端该做什么）

把 21 篇逐篇读完后，发现这套内容的**规整度极高**，这是前端能自动出彩的前提：

| 结构要素 | 覆盖情况 | 前端可利用点 |
|---|---|---|
| `# 标题——副标题` | 21/21 | 拆成主副标题，首页地图用主标题、文章页用副标题做副题 |
| 顶部 `> 引言` blockquote | 21/21 | 渲染为引言卡（lead），不做普通引用样式 |
| `## N. 章节` | 21/21，节号连续 | 自动生成 TOC；节号即稳定锚点 |
| `## N. 边界与不足` | 20/21 | **独立的"边界卡"视觉**，带警示语气 |
| `## N. 一句话总结` | 21/21 | **总结引用块**，系列的高频记忆钩子 |
| `**证据索引**：` / `**参考**：` | 21/21 | 页脚"来源"区，路径渲染成代码 chip，外链渲染成引用 chip |
| `**演进注记(...)**` | 散落 12+ 篇 | 结构化抽出 → 喂给 M1→M7 时间轴 |
| 表格 | 40+ 张 | 宽表转卡片（移动端）；`00/15/20` 三张表是**核心信息图** |
| ASCII 图（``` 围栏） | 7 处 | 逐个替换为真 SVG / 交互组件 |
| `XX 篇` 交叉引用 | 高频 | **自动链接化**，把线性文章变成可跳转的知识图 |

### 四份"不可替代"的独家资产

这四份是别的教程不会有的东西，也是本站的演示效果的真正来源：

1. **两派会师接口图**（15 篇 §2）——系列的思想高潮：确定性栈 × 学习派，两个插槽是唯一交换介质。
2. **路线复盘表**（15 篇 §3）——8 条决策的"第一版 → 最终版 → 性质 → 教训"，是"演进注记"这一写作习惯的完整样本。
3. **能力负声明**（01 篇 §4 + 12 篇）——`force_control: available: false`，"诚实工程"的代表物。
4. **五层 → 六层世界模型**（09 篇 §4）——一个具体的架构演进样本，可点开看每层职责。

另有三份在业界篇里同样重量级（**三流派对比** 18 篇 / **业界定位图** 20 篇 / **数据飞轮三层** 19 篇），列为可选扩展。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite 7 + React 19 + TypeScript | 交互组件多，需要成熟的组件模型与构建速度 |
| 路由 / SSG | **React Router v7 framework mode + 官方 `prerender`** | 公开博客站必须有真静态 HTML（SEO / 首屏），框架自带预渲染与代码分割，少写胶水 |
| Markdown | `react-markdown` + `remark-gfm` | 表格、列表、链接全支持；自定义插件机制成熟。**不自研解析器** |
| 语法高亮 | `rehype-highlight`（highlight.js） | 本系列代码块少且短，够用且轻 |
| 样式 | CSS Modules + CSS 变量设计令牌 | 无 UI 框架依赖，视觉完全可控；深浅双主题只换令牌 |
| 部署 | **暂缓**：先保证 `npm run build` 产出可直接本地打开的 `dist/` | 部署路径到 M1 末尾再定；构建期把 `base` 抽成单一常量，后续无论挂 `/embodied-ai/` 子路径还是独立域名，改一行即可 |

> 若官方 framework mode 的预渲染出现水合不一致，退路：改用 library mode + 自写 60 行预渲染脚本（`StaticRouter` + `renderToString`），产出 `dist/chapter/<id>/index.html` 并补 `404.html`。

    │   ├── markdown/
    │   │   ├── render.tsx     # Markdown 渲染器 + 组件覆盖
    │   │   └── plugins/       # remark 插件
    │   │       ├── cross-refs.ts    # 「XX 篇」→ 内部链接

    │   │   ├── article/       # ArticleShell / Lead / BoundaryCard / SummaryQuote / Evidence / Table / CodeBlock
    │   │   ├── map/           # SeriesMap（首页系列地图）
    │   │   └── interactive/   # ★ 四个签名交互
    │   │       ├── TwoSchools.tsx      # 两派会师接口图
    │   │       ├── MilestoneTimeline.tsx # M1→M7 演进时间轴
    │   │       ├── CapabilityCard.tsx   # 能力卡 / 负声明
    │   │       └── WorldModelLayers.tsx # 五层→六层
    │   └── styles/            # tokens.css / global.css
    ├── scripts/

```

**职责边界**：`scripts/build-content.mjs` 只做"切"，不做"渲染"——输出结构化 JSON；渲染全在 React 侧。

## 3. 内容管线（构建期）

### 输入
`web/` 上一级的 21 个 `.md`，按文件名前缀 `00`–`20` 排序。

### 产出 `app/content/generated/chapters.json`

```jsonc
{
  "id": "15",
  "slug": "15总结",
  "filename": "15总结.md",
  "track": "knowledge",          // knowledge(00-15) | industry(16-20)
  "title": "总结——两派会师与路线复盘",
  "titleShort": "总结",           // 破折号前
  "subtitle": "两派会师与路线复盘", // 破折号后
  "lead": "确定性栈的篇章到此收束……",
  "sections": [
    { "id": "s1", "no": 1, "title": "全系列的知识地图",
      "kind": "normal",            // normal | boundary | summary
      "body": "…" }                 // 原始 markdown 片段
  ],
  "evidence": { "label": "证据索引", "items": ["AGENTS.md", "docs/validation/*"] },
  "evolutionNotes": [ { "title": "mock → 真求解器", "text": "…" } ],
  "prev": "14", "next": "16"
}
```

`meta.json` 另存系列级信息：分轨、双线（知识线/业界线）、快照日期 `2026-10-24`。

### 解析要点
- **不引入 frontmatter**：标题从 `#` 行按 `——` 拆分；节号从 `## N.` 提取；轨道从序号区间判定（`00–15` 知识线，`16–20` 业界线）。原文因此**完全不用改**。
- **`kind` 分类**：节标题命中 `边界与不足` → `boundary`；命中 `一句话总结` → `summary`；其余 `normal`。
- **证据索引**：`---` 之后、`**证据索引**：` / `**参考**：` 开头的尾段单独抽出为 `evidence`。
- **演进注记**：正文里 `**演进注记**` 开头的加粗块级段落抽出为 `evolutionNotes`。
- **交叉引用**：段落正文中 `(\d{2})\s*篇` 抽成 token 列表，运行时由 remark 插件还原为链接（`05 篇` → `/chapter/05`）。

## 4. 渲染层规范

Markdown 由 `react-markdown` 渲染，`components` 覆盖实现下列语义化样式：

| 内容 | 渲染成 | 设计要点 |
|---|---|---|
| 顶部引言 | **引言卡** | 左侧品牌色竖线 + 稍大字号，不做普通灰引用 |
| `## N. 标题` | 带节号的标题 | 锚点 `/chapter/15#s2`，滚动时高亮 |
| `边界与不足` 节 | **边界卡** | 容器化 + 顶部"边界与不足"徽标 + 警示色左边框；与正文明显区隔 |
| `一句话总结` 节 | **总结引用块** | 品牌色大字重引号、放大字号，整篇的视觉落点 |
| 表格 | 语义化 `<table>` | 桌面保留；窄屏（<720px）转成"字段: 值"卡片列表 |
| 代码围栏 | 代码块 | 等宽、行号可选、复制按钮、横向滚动 |
| ASCII 图 | **真 SVG**（见 §5） | 原始 ``` 块保留在源码里，渲染时被替换 |
| `XX 篇` | 内部链接 | 下划线 + 悬停显示目标篇名 |
| 证据索引 | 页脚来源区 | 路径 → 等宽 chip；外部 URL → 带 ↗ 的引用 chip |

**交叉引用链接化**是知识传递的关键机制：原文中"05 篇详述""12 篇会再次出现"这类跨篇指引遍布全书，把它们变成真链接后，21 篇从"线性长文"变成"可跳转的知识网络"。

## 5. 四个签名交互（演示效果的核心）

> 原则：**不把每篇都做成动画**。交互只放在"文字讲不清、看图才懂"的地方。其余 17 篇保持纯阅读体验——那是知识的载体，不是演示的载体。

### 5.1 两派会师接口图 —— 源自 15 篇 §2

- **形态**：分层 SVG。上层"学习派（未接入，插槽已留）"，中层两个交换插槽（`Runtime API` / `Skill Manifest`），下层"确定性栈（BT 编排 → 协调调度 → 世界模型 → MoveIt 规划 → SafetyCheck → JTC → Gazebo/真机）"，底部回环"Episode + 域随机化 → 数据集"。
- **交互**：点击任一层 → 右侧展开该层职责、对应篇号入口；点击两个插槽 → 高亮交换介质并说明"为什么 M6.5 要刻意做成非自然语言"。
- **承载知识**：分层共生的架构判断；学习派与确定性栈的分工边界。
- **位置**：15 篇 §2 原 ASCII 图处 + **首页 Hero**（系列的论点即门面）。

### 5.2 M1 → M7 演进时间轴 —— 源自 15 篇 §3 + 各篇演进注记

- **形态**：横向时间轴，M1…M7 为节点；每个节点挂一条演进注记。
- **交互**：点击节点 → 展开该里程碑的"第一版 → 最终版 / 性质 / 教训"三段式卡片（如"协调栈：order_manager 大杂烩包 → multi_arm_core 薄编排 + 子模块 / 重构未完成 / 过渡期最容易变成永久期"）。
- **承载知识**：**技术路线不预设正确**这一写作原则的具体证据链；让读者看到"回摆""补丁后升级"是常态。
- **位置**：15 篇 §3 表格处；各篇正文的 `**演进注记**` 块旁给出"在时间轴上查看"跳转。

### 5.3 能力卡 —— 源自 01 篇 §4 + 12 篇

- **形态**：卡片组，每张卡一项能力（关节数 / 控制器数 / 工作空间 / 力控 / 感知 / 抓取 …）。
- **交互**：顶部开关"能力 / 边界"；切到"边界"模式时，`force_control: available: false` 这类**负声明卡片高亮**，展示 `reason` 与 `conflicts_with: ["manipulation"]`。
- **承载知识**：能力边界是一等公民；12 篇 A1–A6 路线性边界的入口。
- **位置**：01 篇 §4 YAML 旁；12 篇 A 类清单旁复用。

### 5.4 世界模型五层 → 六层 —— 源自 09 篇 §4

- **形态**：左侧五层（Entity/State/Relation/History/Prediction）纵向堆叠，右侧滑出第六层 Belief 层。
- **交互**：点击任一层 → 展开职责与典型内容；点击"Belief" → 展示 `GaussianBelief`（3D 位置 + 对角协方差 + 置信度 + 来源）与 `uncertainty = 协方差迹/3` 公式，并对比"确定性快照 + 标志位"的旧版。
- **承载知识**：从布尔量掩盖概率问题到概率信念的一次具体架构升级。

### 可选扩展（有余力再做）

- **业界定位图**（20 篇）：8 行"业界标配 vs 项目现状"，按"路线性 / 工程性 / 已达标"三态着色。

## 6. 知识传递机制（不止于好看）

演示效果吸引人进来，知识传递决定人留不留。这里是具体机制清单：

| 机制 | 实现 | 解决的认知问题 |
|---|---|---|
| **交叉引用链接化** | remark 插件把 `XX 篇` 变成内部链接，悬停显示目标篇名 | 读者知道"这一句的展开在别处"，不会漏读 |
| **边界卡 + 总结块** | 全站一致的视觉语言，每篇都有固定的"边界"和"一句话"落点 | 每篇 6 分钟左右能抓到一个可复述的结论 |
| **双线阅读路径** | 首页显式给出两条路径：知识线 00→15（确定性栈 → 学习派）、业界线 16→20（2024–2026 产业） | 21 篇一次性读完不是必须；给出可完成的最小阅读单元 |
| **术语表** | 手工维护 `glossary.ts`：术语 → 一句话解释 → 首见篇号 → 锚点；正文中的术语首次出现加下划虚线，悬停出解释 | 双臂/仿真/具身这些词有门槛，不能让读者去查 |
| **证据强度标注** | 16–20 篇的"待复现 / 媒体口径 / 厂商口径"提取为徽标 | 读者建立"哪些结论有证据、哪些只是报道"的判断力 |
| **阅读进度追踪** | localStorage 记录已读篇目，首页地图上以填充态显示 | 可见的进度条本身就有驱动作用 |
| **自测题（可选）** | 每章 1–3 题手写（存 `quiz.ts`），答错进错题本（localStorage） | 提取练习是长期记忆的唯一有效手段；这是可选阶段，不强塞 |

> 术语表与自测题是**手工内容**，会占用真实工作量。二者都是"知识传递"而非"演示效果"，按剩余精力决定是否做——先做前五项。

## 9. 风险与取舍

| 风险 | 应对 |
|---|---|
| 预渲染水合不一致 | 优先用框架自带预渲染；退路是 library mode + 自写预渲染脚本 |
| 交互件喧宾夺主 | 硬规则：交互只出现在 4 个签名位置；其余篇目纯阅读 |
| 手工内容（术语表/自测题）成本高 | 列为可选阶段，先用自动化机制（交叉引用、边界卡、总结块、进度）打底 |
| 中文排版细节 | 正文行高 1.9、字距微调、`PingFang SC / Noto Sans SC` 优先；ASCII 图必须等宽字体 + 保留空白 |
| 宽表在移动端溢出 | <720px 统一降级为卡片式行 |
| 与仓库其他系列的关系 | 站点只服务 `embodied-ai/`，但内容管线按"任意目录的 md 集合"设计，未来可复制到其他系列 |

## 10. 已确认决策

- [x] **站点标题**：用一台双臂机器人打开具身智能的大门（沿用系列导言原句）。副标题用「70% 知识 + 30% 项目」的立场。

- [x] **源码外链**：**只显示路径文本，不做 GitHub 外链**。证据索引里的 `multi_arm_line_ws/...` 等路径渲染为等宽 chip，纯文本，不产生外链。
