# 数据与模仿学习——机器人从"看"中学会做事

> 前十一章的机器人，每个行为都是人写的。从这一章开始换范式：行为不从代码来，从数据来——给模型看一万遍"人类怎么抓杯子"，它就学会抓杯子。这就是模仿学习（Imitation Learning），当前具身智能数据飞轮的第一级。

---

## 1. 为什么是模仿学习先起飞

让机器人"从零学做事"有两条路：强化学习（试错 + 奖励）和模仿学习（看示范 + 复现）。操作任务上**模仿学习先起飞**，原因有三：

- **奖励设计难**：抓杯子成功与否容易判定，"抓得优雅"几乎无法写成奖励函数；RL 在操作上的样本效率至今撑不起真实机器人训练；
- **示范便宜**：人做一遍就是一条完美示范——遥操作设备（VR 手柄、动捕、外骨骼）让"数据采集"变成"干活本身"；
- **起点高**：预训练视觉/语言骨干带来了"常识"，模仿学习只需在行为层微调。

## 2. 模仿学习的两个核心技术问题

**问题一：分布漂移（compounding errors）。** 行为克隆（BC，最朴素的模仿学习）假设"状态 → 动作"映射是静态的。但执行中一点点误差会让机器人滑出示范数据的分布——没见过的状态 → 更错的动作 → 更偏的状态，误差雪崩。缓解方案：DAgger（让专家给偏移后的状态再标注）、或用更强的策略表示。

**问题二：多模态动作分布。** 同一个状态下"往左绕"和"往右绕"都是好动作，MSE 回归会把两者平均成"撞墙"。这直接催生了当前两大主流策略表示：

- **扩散策略（Diffusion Policy）**：把动作序列生成建模成扩散去噪，天然表达多模态；
- **ACT（Action Chunking with Transformers）**：预测**动作块**（一次输出未来一小段动作序列）+ CVAE 隐变量——来自 ALOHA 项目，"动作分块"从此成为标配。

## 3. 遥操作：数据飞轮的踏板

当前操作数据的主流采集方式是**遥操作**（teleoperation）：人操纵主端（VR/动捕），从端（机器人）跟随，全过程录制成"观测-动作"对。著名标本是 **ALOHA / Mobile ALOHA**：低成本双臂遥操平台 + ACT 策略，用几百条演示学会系鞋带级别的精细任务——它证明了两件事：数据质量比数量先行，以及**采集硬件本身可以是开源工程**。单条演示是"观测流 + 动作流"，这正是数据集的基本格式。

## 4. 数据的规模与共享

具身数据的"ImageNet 时刻"尝试是 **Open X-Embodiment**：几十个机构、多种机器人形态、上百万 episode 的联合数据集——**跨具身**（cross-embodiment）训练由此成为共识（不同的臂、不同的夹爪，动作空间不同，如何共享数据是核心难题）。数据格式的事实标准之一是 Hugging Face 的 **LeRobot** 格式（14 篇）。

## 5. 项目实例：仿真数据流水线与 Episode 的"可重放"设计

项目没有任何学习组件（12 篇 A5），但它在 M6 造的**数据基础设施**恰好是模仿学习需要的"数据飞轮"前半圈：

- **M6.S 仿真平台**：场景生成器（随机生成多样化场景）、**域随机化**（光照/纹理/位置/物理随机化——sim2real 的第一件武器，14 篇）、GT 标注免费提供、Dataset Pipeline（`Gazebo → 数据集自动采集`）。设计文档里有一句定位性原话：**"Simulation 是 Runtime 执行环境之一，不是事后验证工具"**——仿真被当作数据工厂，这个定位对学习派项目是常识，对一个确定性栈项目是超前的自觉；
- **M6.4 Experience Infrastructure**（`multi_arm_experience`）：核心类型是 `Episode`——"initial world state → execution steps → result → recovery → final state"，源码注释特别强调 **"This is NOT a log entry. It is a structured, replayable record of what the robot experienced during one task"**（世界状态快照 + 关系 + 时间戳，可反序列化重放）。配套 `experience_recorder`（记录）、`failure_analyzer`（失败归因）、`dataset_exporter`（导出数据集）。Episode 里连 recovery 都记了——失败数据被保留而不是丢弃，这是数据工程里容易被忽略的正确姿势（失败示范本身是宝贵的负样本）。

**演进注记**：M6.4 叫"Robot Experience Infrastructure"，M6.S 的 Dataset Pipeline 是后补的横向层（"第四轮调整"加入）——数据采集先于数据集化，和项目其他部分一样是长出来的。**这条数据流水线从头到尾没有被消费过**：`dataset_exporter` 导出的数据集，仓库里没有模型去训练它——基础设施先行，消费者缺席（15 篇路线复盘的又一例）。

## 6. 边界与不足

数据量级差几个数量级（本项目的 episode 是"百"级且全部来自确定性策略，Open X-Embodiment 是百万级、来自多形态真机）；无遥操作（仿真里没有"人"，示范 = 确定性策略自己的成功轨迹，学它 = 学自己）；无人在环的失败恢复示范；GT 标注没有流向训练（10 篇已提）。但基础设施的形状是对的：**域随机化 + 可重放 Episode + 失败归因 + 数据集导出**——把这四件东西接到任何一个模仿学习框架上，就是一条可用的训练流水线。

## 7. 一句话总结

> 模仿学习的本质是"把人的技能变成数据，再把数据变成策略"；它起飞的三个条件——便宜的采集、好的策略表示（扩散/动作块）、共享的数据底座——项目已经自发备齐了第三件的一半。
