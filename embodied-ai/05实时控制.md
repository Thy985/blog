# 实时控制——ros2_control 与机器人的小脑

> 规划层给的是一份"未来几秒"的轨迹，真正的动作发生在毫秒级：控制器以几百赫兹的频率把轨迹切成每周期一个的关节指令。这一层叫 ros2_control——它慢到人眼可辨，快到 AI 的思维链追不上，是机器人的"小脑"。

---

## 1. 控制器管理器：插在硬件上的软件层

**ros2_control** 是 ROS 2 的实时控制框架，核心是三个概念：

- **Controller Manager（CM）**：装载并调度所有控制器，管理它们的生命周期（loaded → active → inactive）；
- **Hardware Interface**：硬件抽象——Gazebo 仿真、UR 驱动、任何能收发关节指令的东西都实现同一个接口。**上层完全不关心下面是真电机还是仿真器**，这正是 sim/real 共享上层栈的物质基础（sim2real 的第一块垫脚石）；
- **Controller**：控制律的封装。同一份硬件接口上，可以热切换不同控制器。

## 2. 控制器家族与频率

**JointTrajectoryController（JTC）**是操作臂的标配：吃一条带时间戳的轨迹，按插值周期跟踪。**JointStateBroadcaster（JSB）**是另一端：把硬件的关节状态以固定频率广播出去（本项目 500Hz），全系统读它来知道"身体现在在哪"。

控制频率的量级感：规划层一秒一两个决策，JTC 50–500Hz 插值跟踪，底层伺服 1kHz+，电流环 20kHz+。**越往下频率越高、语义越简单**——每一层把上一层"几秒的意图"翻译成"下一层每毫秒的指令"。

## 3. 轨迹从规划到关节的四跳

```
MoveIt 输出: [(t₁, q₁, q̇₁), (t₂, q₂, q̇₂), ...]   （秒级，几十个点）
  → JTC 插值: 每 2ms 算一次当前时刻的目标关节角    （百赫兹）
    → Hardware Interface: 写关节指令/读编码器       （周期同步）
      → Gazebo/电机: 物理执行
        → 编码器 → JSB → /joint_states (500Hz) → 全系统
```

注意回环：JSB 发布的 500Hz 关节状态是**全系统的实时真相**——规划层用它校验执行结果，WorldModel 用它更新身体状态，而它**不进** WorldModel 的缓存（AGENTS.md 架构规则第 4 条：ros2_control 是实时控制真相源，500Hz joint_states 不进 WorldModel——两个真相源分离，09 篇详述）。

## 4. 什么时候停：halt 语义

控制系统最关键的代码路径不是"怎么动"，是**"怎么停"**。JTC 的 halt（急停去激活）语义：停止发送新指令、保持或安全释放当前状态。E-Stop 的完整链路：SafetySupervisor 判定 → 请求 CM 将 JTC 置 inactive → 控制器停止跟踪 → 臂停在当前位置 → 系统进入 ERROR 态，**重启恢复需要显式流程**（07 篇详述）。

## 5. 项目实例：7 个控制器与一次 E-Stop 的解剖

M7.1 升级后的控制器清单（`ros2 control list_controllers`）：

```
head_controller                   JTC  active
torso_controller                  JTC  active
arm1_joint_trajectory_controller  JTC  active
arm1_gripper_controller           GripperActionController  active
arm2_joint_trajectory_controller  JTC  active
arm2_gripper_controller           GripperActionController  active
joint_state_broadcaster           JSB active
```

16 个关节、7 个控制器、一个 CM。夹爪走独立的 `GripperActionController`（action 接口，语义是"夹/松"而非"跟踪轨迹"）。M4.3 的安全闭环验收里，E-Stop 链路被实测：**运动中触发 E-Stop → JTC inactive → Robot ERROR**，且 Coordinator 进程被杀后 SafetySupervisor 依然可用（安全面独立于主控，07 篇）。

**演进注记（mock → Gazebo → 16 关节）**：控制层的硬件接口换了三次——M1–M3 的 mock controller（轨迹写进内存就回成功）、M4 的 Gazebo、M7.1 的 16 关节扩展。**上层栈（MoveIt/调度/安全）一次都没有改**——这就是"Hardware Interface 抽象"的红利，也是 sim2real 第一垫脚石的实证。

## 6. 边界与不足

500Hz 是 Gazebo 联合仿真节奏，不是硬实时内核（无 PREEMPT_RT/ Xenomai，真实 1kHz 伺服环缺席）；无力控接口（`capability.yaml` 负声明：`UR5e simulation has no force control`）——阻抗控制、柔顺装配这一整个世界不可达；Gazebo 的物理引擎是"够用的近似"，接触刚度、摩擦锥与真实电机特性有系统性偏差；控制器切换（M5.1 的 ControllerFailureHandler）只验证过 fallback 到 abort，没有验证过热切换降级运行。

## 7. 一句话总结

> 控制层的全部要义是两个"真相"：500Hz 的关节状态是身体唯一的实时真相，而 E-Stop 链路是唯一必须在任何状态下都走得通的路。上层栈可以重写，这两条不能破。
