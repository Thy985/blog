# 运动规划——从"到得了"到"怎么去"

> IK 告诉你目标姿态存在解，运动规划负责找到一条从起点到目标的**无碰撞路径**。在 6 维以上的构型空间里穷举是不可能的，这一章的主角因此是"采样"——以及采样式规划带来的所有下游麻烦：路径质量、求解时间、失败率。

---

## 1. 构型空间：规划真正发生的地方

运动规划不在三维工作空间里进行，而在**构型空间（C-space）**：一个 N 关节机器人的构型空间是 N 维流形，每个点是一组关节角。障碍物被"提升"进 C-space：工作空间里一个盒子，在 C-space 里是一整片禁区。

这个抽象的威力在于把规划问题变成"高维空间里两点连线绕开禁区"——但也带来诅咒：6 关节的 C-space 是 6 维，12 关节（双臂）是 12 维，网格/栅格类穷举方法直接出局。

## 2. 采样式规划：概率完备的赌徒

高维 C-space 的主流答案是**采样式规划**（OMPL 是这一家的集大成库）：

- **RRT/RRT\***：从起点随机撒点、向随机点生长树、碰到障碍就绕，直到枝条够到目标。RRT* 在生长中重连父节点，让路径渐近最优。
- **PRM**：先撒一张随机路网，之后每次规划只需图搜索——适合静态环境反复规划。
- **关键性质**：概率完备（有解则求解时间趋于收敛）但**不保证最优**、**不保证稳定时间**——同一个查询，今天 0.3 秒明天 3 秒，是常态而非故障。

规划出的路径还要**后处理**：shortcut（剪掉来回绕的段）、时间参数化（把几何路径变成带速度/加速度的时间轨迹，如 TOTG），才是一份可执行的轨迹。

## 3. 碰撞检测：规划层的"物理引擎"

采样规划器每次生长一步都要问"这个构型安全吗"——碰撞检测因此是规划层最热的路径：自碰撞（SRDF 允许忽略的碰撞对要预先剔除）、与环境碰撞、（双臂时）臂与臂互撞。工程上的常见技巧：先粗后精（包围盒 → 精确网格）、FCL 等库的复用、以及把"肯定不碰撞的碰撞对"在 SRDF 里白名单掉。

## 4. 规划失败学

采样规划器必然有失败率，成熟的操作栈把失败当流程节点而非异常：

1. 规划失败 → **放宽约束**再试（放弃姿态约束、加大目标容差）；
2. 仍失败 → **换抓取姿态**（不同的 approach 角度）；
3. 仍失败 → 释放资源、宣告失败、走恢复链。

失败处理的深度，是区分"demo 栈"和"系统栈"的标志。

## 5. 项目实例：MoveIt2 全链路与一个真实的失败恢复链

项目用 MoveIt2 做 L3 运动规划层，完整链路：`任务 → Coordinator → SafetySupervisor 审批 → MoveIt2 规划 → JTC 执行 → Gazebo`。M4.5 的验收数字：OMPL + KDL，`dual_arm` 组 12 关节一次规划 13 个轨迹点。

M5.1 恢复框架把第 4 节的理论变成了代码（`src/multi_arm_recovery/handlers/`）：

```
PlanningFailureHandler   规划失败 → 放宽约束重规划
CollisionHandler         碰撞 → 退回安全位 → 重规划
ResourceTimeoutHandler   资源超时 → 释放 → 重新分配
ControllerFailureHandler JTC inactive → 切换控制器 / abort
GraspRetryHandler        抓取失败 → 重试（最多 3 次）
```

**演进注记（三层验收的教训）**：M4/M4.5 验收的是"组件存在且能工作"，M4.6 才补上"系统作为一个整体自主完成任务"（158 tests），M5.6 压力测试再补"面对随机参数和失败注入的鲁棒性"。AGENTS.md 对这个渐进的自我批评很直白：M4 时"未证明系统作为一个整体自主完成任务"——**每个能力都是被上一层的验收暴露缺失后才补的**，规划层的失败处理（M5.1）晚于自主闭环（M4.6）就是一例。

## 6. 边界与不足

OMPL 用默认参数集，没有针对 UR5e 调优（planning time、goal bias 都在默认值）；"动态障碍重规划"（M5.6 Level 2）验证过但路径是"停→重规划→走"，没有真正的在线重规划；双臂联合规划的时间成本没有单独基准化；规划超时策略简单（超时即失败，无 anytime 规划——先拿次优解先走）。

## 7. 一句话总结

> 高维构型空间里没有精确解，只有采样和概率——所以规划层的工程学不在算法本身，而在失败率的管理：放宽、重试、退让、宣告，每一步都有去处。
