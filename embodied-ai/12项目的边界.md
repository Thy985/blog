# 项目的边界——确定性栈解决不了什么

> 前面十一篇的"边界与不足"小节，各自记住了一块短板。这一篇把它们集中起来：六个能力局限（A 类），按"现状 → 为什么 → 学习派的需求"整理。这份清单不是检讨书——**确定性栈的每一条边界，都精确指向学习派的一个入口**。

---

## 1. 先说清楚"边界"的坐标系

一个仿真项目的"做不到"分两种：**路线性的**（这条技术路线在此约束下走到头了，换路线才有解）和**阶段性的**（继续投入可以解决，只是还没做）。本篇只收路线性的——它们不会因为多写代码而消失，只会因为**换了范式**而消失。阶段性的问题（OMPL 没调参、技能没实测回填、迁移没执行完）归入 15 篇的路线复盘。

## 2. 六条路线性边界

**A1 纯仿真，无真机。** 现状：WSL2 + Gazebo Harmonic，AGENTS.md 把 Sim2Real 标为"远期"，M6 的 Sim2Real 规划只有"benchmark 对比仿真 vs 实体执行数据"一张验收模板，从未执行。为什么是路线性的：真实电机、真实接触、真实噪声是**另一套物理**，不是参数调优能补的。→ 学习派需求：**sim2real 全套**（域随机化、真机微调、reality gap 度量，14 篇）。

**A2 抓取是逻辑附着，不是接触物理。** 现状：M6.2 验收通过条件明写"模拟 attach/detach"，Robotiq URDF 未加载（标 ⬜）。为什么路线性：无力控、无力传感的前提下，接触物理无从谈起。→ 学习派需求：**触觉与力反馈的感知-操作**（这是 Diffusion Policy 一类灵巧操作研究的入场费）。

**A3 无力控。** 现状：`capability.yaml` 的负声明——`force_control: available: false, reason: "UR5e simulation has no force control"`，`conflicts_with: ["manipulation"]`。为什么路线性：UR5e 仿真接口只暴露位置控制；阻抗/导纳这一整个控制族不可达。注意这个声明本身是项目的优点：**能力边界被建模成数据**，上层（Skill 的 required_capabilities）可以查询"这个机器人不会力控"。→ 学习派需求：力控基座（真机 + 力矩接口，如 Franka 类平台）。

**A4 感知是古典的。** 现状：颜色阈值检测 + GT 直读，M7.4/M7.5 的 0.015m vs 0.038m 差距（10 篇）。为什么路线性：颜色阈值在真实世界的脆弱性（光照、纹理、遮挡、堆叠）是原理性的，不是阈值能调好的。→ 学习派需求：**可泛化的开放词汇感知**（检测/分割/6D 位姿估计的基础模型）。

**A5 零学习组件。** 现状：全仓库无 torch、无 LLM 调用、无策略网络——任务规划是 BT，技能是手写 YAML，世界模型的关系是手工规则。为什么路线性：这不是"还没来得及"，是整个项目的定位——它验证的是**确定性栈能走多远**。→ 学习派需求：从数据学技能（13 篇）、VLA 策略（14 篇）。

**A6 没有语义与语言的入口。** 现状：Runtime API 刻意"非自然语言"（M6.5 命名决策），"pick red_cube" 里的 "red" 是靠颜色阈值接地，"收拾桌面"这类语义指令无承接者。为什么路线性：语义理解本来就是 LLM 的领地，确定性栈不越界——但**插槽留好了**（Skill 词表 + Runtime API）。→ 学习派需求：LLM/VLA 的任务理解层（14 篇）。

## 3. 这份清单的正确读法

六条边界拼起来是一张**接口图**：确定性栈（本项目）负责身体、空间、运动、安全、协调、世界记账——它把"动作的正确性"做到了可验证；学习派负责感知泛化、力觉操作、语义理解、技能习得——它把"行为的获得"变成数据问题。两边在各篇留下的插槽上对接：

| 项目的插槽 | 学习派的对接物 |
|---|---|
| `capability.yaml`（含负声明） | VLA 的能力声明 / 安全壳的白名单 |
| Skill Manifest（五要素 + cost） | LLM 选技能的词表（SayCan 式） |
| Runtime API（非自然语言） | 上层策略的动作接口 |
| WorldModel belief | 学习型世界模型的先验/验证器 |
| Episode 记录 + 域随机化 | 模仿学习的数据集（13 篇） |
| Gazebo + Hardware Adapter | 仿真训练环境 + sim2real 通道（14 篇） |

## 4. 一个反直觉的结论

这六条边界不是这个项目的失败清单，而是它的**主要产出之一**。一个没有 A1–A6 的项目（比如直接上一个 VLA demo）反而无法告诉你：安全为什么要独立、技能为什么要有前后置、世界模型为什么要分层——**确定性栈的价值要在学习派缺席时才看得清**，因为它定义了学习派必须遵守的那些"不变量"（安全审批、能力声明、可验证的前后置）。

## 5. 一句话总结

> 确定性栈的边界清单，就是学习派的需求清单——接口已经留好，下一章开始讲从数据学行为的第一种范式：模仿学习。
