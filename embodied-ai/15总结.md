## 2. 两派会师：一张接口图

把 12 篇的插槽表和 14 篇的分层混合图合起来，就是这张系列一直在逼近的图：

```
        ┌─────────────────────────────────────────┐
        │  学习派（未接入，插槽已留）                  │
        │  VLA / LLM：语义理解、技能选择、策略生成      │
        └───────────────┬─────────────────────────┘
             Runtime API │ Skill Manifest（词表+cost）
        ┌───────────────▼─────────────────────────┐
        │  确定性栈（本项目，M1–M7 全部就位）           │
        │  BT 编排 → 协调调度 → 世界模型 → MoveIt 规划 │
        │  → SafetyCheck → JTC → Gazebo/真机         │
        └───────────────┬─────────────────────────┘
                        │ Episode + 域随机化 → 数据集
             （数据飞轮的回程：学习派吃掉它，再学出上层）
```

关键判断（14 篇的结论，此处定稿）：**不是谁取代谁，是分层共生**。学习派出"做什么"，确定性栈出"怎么安全地做"和"做过的记录"。两边交换的介质就是中间那两个插槽——这也解释了为什么 M6.5 要把 Runtime API 刻意做成"非自然语言"的能力接口。

## 3. 路线复盘：哪些是一开始没想好的

各篇"演进注记"的总账。评判标准按 00 篇的约定：**当时约束下可辩护即为合理**，重点记录转折本身。

| 决策 | 第一版 | 最终版 | 性质 | 教训 |
|---|---|---|---|---|
| 协调栈 | `order_manager`（大杂烩包） | `multi_arm_core` 薄编排+子模块 | 重构未完成 | 迁移评估写了 v1/v1.1 两版，**双轨并存至今**——"过渡期"最容易变成"永久期" |
| 双臂控制 | M4.2 每臂独立 CM | M4.5 合并 URDF 单 CM | 架构回摆 | 隔离性与联合规划不可兼得；回摆由需求（跨臂避撞）倒逼，非预判 |
| BT 插件 | async 回调里建临时节点 | 共享 Node + AsyncTick | 写错→重构 | 死锁出现在**双臂并发**才暴露——单臂测试给不了并发自信 |
| 任务协议 | 字符串 `"arm1:zone_a:ready"` | `TaskGoal.msg` 领域模型 | 补丁后升级 | 字符串协议是 M1 的合理起点；**向后兼容层（双解析并存）是补丁的正式形态** |
| 世界模型 | 五层（确定性快照+标志位） | 六层（+BeliefLayer，修 6 缺陷） | 二期升级 | v1 用布尔量掩盖概率问题是可原谅的；**关键是不把 v1 冻结成教条** |
| 感知 | GT 直读 | "Real Perception"（仍是 OpenCV） | 命名先于内容 | 验收项名字比内容先到终点——"real"的语义漂移值得每个验收表警惕 |
| 平台规划 | — | M6 计划经四轮架构评审 | 规划迭代 | 大规划本身也要小步走；四轮评审是诚实的成本 |
| 文档 | — | AGENTS.md 顶部"M5 当前" vs 底部"M7 完成" | 文档漂移 | Agent 深度协作项目里文档就是 Agent 的世界观，漂移代价被放大 |

**工程债盘点**（选择性，有教训的）：双轨并存（上表）、测试结构失衡（125 个 mock 测试文件 vs 13 个涉 Gazebo——"测试不依赖 Gazebo"纪律的收益是 CI 稳定，代价是真实仿真路径覆盖薄）、数据流水线无人消费（`dataset_exporter` 导出的数据集没有模型去训练）。**代码卫生本身无债**：全仓库 TODO/FIXME 仅 2 处——Agent 协作 + 强约束 AGENTS.md 的开发模式在代码整洁度上是成功的。

## 5. 可迁移清单

- [ ] **两个真相源分离**：认知真相（世界什么样）与实时真相（身体此刻）分开持有，频率与职责都不同（05、09 篇）
- [ ] **安全三宪法**：权力独立、默认拒绝（fallback 方向由语义决定）、横切拦截（06、07 篇）
- [ ] **能力含负声明**：机器人不能做什么要和数据一样是一等公民（01、12 篇）
- [ ] **先冻结接口再盖楼**：M5.7 freeze → M6.3 SPEC → 上层敢依赖（11 篇）
- [ ] **失败是流程节点**：放宽 → 重试 → 退让 → 宣告，每步有去处（04 篇）
- [ ] **能用互斥消灭的碰撞不靠规划**（08 篇）
- [ ] **仿真当数据工厂不当验证工具**（13 篇）
- [ ] **Episode 是可重放的结构化记录，不是日志**（13 篇）
- [ ] **演进注记习惯**：每个架构决策记录"第一版是什么、为什么变"——文档漂移的解药（00 篇约定、本篇 §3）
- [ ] **单臂测试给不了并发自信**：双臂死锁的教训，适配到一切"规模才暴露"的 bug（06 篇）

## 6. 收束

三个系列的共同主题在这个系列里最完整地显形：weather 系列讲"测量的诚实"，prime-rl 系列讲"复制的诚实"，这一系列讲**"能力的诚实"**——一个机器人系统最珍贵的产出，不是它 10/10 的验收通过率，而是它敢于声明 `force_control: available: false` 的那张 capability 清单。

这台"纸面人形"停在了学习派的门口：下半身齐备，上半身空白，接口插孔擦得锃亮。**门后的世界在业界篇（16–20）展开**——产业全景、VLA 第三代、世界模型三流派、数据生态，以及修正后的路线图；门后最后一个房间（20 篇）是系列的终章。
