# 系列导言：用一台双臂机器人打开具身智能的大门

> 大语言模型回答问题，具身智能改变世界。这一系列以我自己的项目——双 UR5e 多机械臂 ROS 2 系统——为线索，把具身智能的完整版图从"身体"讲到"大脑"，从确定性的经典机器人栈讲到学习派的 VLA。70% 是知识，30% 是这个项目的实例。

---

## 1. 为什么是这个项目

[multi_arm_line_ws](https://github.com/Thy985/multi_arm_line_ws) 是我造的一台"纸面人形"：双 UR5e 机械臂 + 躯干 + 头部（RGB-D + IMU），跑在 ROS 2 Jazzy + Gazebo Harmonic 上，从接口架构一路做到具身操作（M1→M7），全程由 AI Agent 深度协作开发。

选它做具身智能的入门线索，有三个理由：

- **它是一个完整栈**。不是某个单点 demo，而是从 URDF 到技能运行时的全链路——具身智能的每一个教科书主题（运动学、规划、控制、行为树、世界模型、感知、抓取、技能、多机、安全、数据），在这个仓库里都有一个真实对应物。
- **它代表"确定性派"**。具身智能有两派：古典派用 OS、规划、控制把行为造出来（ROS/MoveIt/行为树——本项目），学习派用数据和神经网络把行为学出来（模仿学习、VLA）。这个项目是前者的完整样本，而它的每一个边界恰好指向后者的入口。
- **它的自我定位就是一台"机器人 OS"**。项目自己的里程碑划分写着：M5 = 机器人 OS 内核，M6 = 机器人 OS 运行时，M7 = 机器人智能层。把机器人当操作系统来造——这个视角本身就是理解具身智能系统侧的最好框架。

## 2. 这个系列怎么读

**每篇的结构**：70% 讲一个具身智能主题的知识（独立于项目成立，不需要 ROS 2 基础），30% 回到项目看这个主题如何落地（给到仓库路径），篇末固定两小节——**边界与不足**（这个主题上项目做到哪、没做到哪）和**一句话总结**。

**知识线（70%）**：身体 → 空间感 → 运动学 → 运动规划 → 实时控制 → 任务编排 → 安全 → 多机协调 → 世界模型 → 感知与抓取 → 技能抽象 → 数据与模仿学习 → VLA 与 sim2real。前半是确定性派的领域，后半进入学习派。

**项目线（30%）**：分散在各篇，最后由两篇收拢——12 篇《项目的边界》把能力局限整理成"学习派的需求清单"，15 篇总结做两派会师和项目复盘。

**业界篇（16–20）**：以 2026-10-24 为调研时点，走出项目看产业——全景（16）、VLA 第三代军备竞赛（17）、世界模型的三个流派（18）、数据仿真与基准生态（19），最后回到项目画定位图与修正路线（20，系列终章）。

## 4. 两个预先声明

**关于"边界与不足"**。这个项目的能力局限（纯仿真、假抓取、无力控、古典感知、零学习组件）和工程债（双轨并存、测试失衡、文档漂移）会和知识一起如实写——不是自曝其短，而是因为**缺陷清单就是学习派的入场券**：确定性栈的尽头，正是模仿学习和 VLA 开始的地方。

**关于"技术路线不预设正确"**。这个项目不是一次设计出来的：协调栈重写过、双臂控制架构回摆过、任务协议从字符串升级成领域模型、身体是 M7.1 才长出来的、平台规划迭代了四轮。凡有转折，各篇的**演进注记**会写明"第一版是什么、什么契机变了"——项目里的每个选择都只代表"当时约束下的一个迭代版本"，不代表最优解，更不代表终局。

**关于 Agent 协作**。这个项目全程由 AI Agent 深度参与开发（55KB 的 AGENTS.md 定义约束、Robot OS Shell 给 Agent 当操作台）。前两个系列写过 Agent 作为实验协作者、Agent 作为研究记录员，这一系列里 Agent 是**建筑工人**——写代码、跑测试、写验证报告。这个工作方式本身也是系列的一个暗线。

## 5. 写作原则

还是那句话：真实项目中最有价值的部分，往往不是配方，而是那些失败、反转和停止信号。这台"纸面人形"最诚实的部分不是 10/10 的验收通过率，而是 `capability.yaml` 里那句 `force_control: available: false, reason: "UR5e simulation has no force control"`——知道自己不能做什么，是一切能力声明的前提。
