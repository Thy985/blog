# 损失函数与信任域——IPO、IcePop 与 mismatch KL

> RLVR 训练崩溃的方式惊人地一致：某个 token 的概率比率飞了，梯度跟着飞，几步之内熵塌缩。所以所有现代 RL 损失都在做同一件事——画一个圈，把出圈的 token 处理掉。区别只在圈怎么画。

---

## 1. 场景设定：为什么要"修正"

异步架构（02 篇）意味着训练的 rollout 是旧策略 π_μ 生成的，而 loss 在当前策略 π_θ 上算。这是离线策略问题，标准解法是重要性加权：每个 token 的策略梯度项乘上比率 π_θ(y_t)/π_μ(y_t)。比率应该≈1，越不≈1，这批数据越"陈"，修正越不可信。

于是所有设计都围绕一个问题：**比率出多大问题，该信到什么程度**。

## 2. IPO：prime-rl 的默认损失

`src/prime_rl/trainer/rl/loss.py` 里默认的 RL 组件叫 IPO（Importance Policy Optimization）：

$$\mathcal{L}(\theta) = \frac{1}{N}\sum_t \left[ -\mathbb{1}\left(\left|\pi(y_t)-\mu(y_t)\right| \le \epsilon\right)\ \tau_A \hat{A}_t \frac{\pi(y_t)}{\mu(y_t)} + \tau_{KL}\log^2\left(\frac{\pi(y_t)}{\mu(y_t)}\right) \right]$$

三个部件：

1. **重要性加权策略梯度**：$\tau_A \hat{A}_t \cdot \pi/\mu$，优势是正的 token 概率被推高，负的被压低。
2. **对称信任域**：注意掩码条件是 $|\pi(y_t) - \mu(y_t)| \le \epsilon$——用**概率的绝对变化**（默认 ε=0.3）判断 token 是否可信，不是 PPO 那种对比率裁剪。一个概率从 0.05 变到 0.3 的 token（比率 6 倍但绝对变化 0.25）会被保留；从 0.8 变到 0.4 的会被砍。直觉：小概率 token 的大比率是学习的正常途径，大概率 token 的塌缩才是事故。
3. **平方对数比 KL 正则**：$\tau_{KL}\log^2(\pi/\mu)$，默认 `kl_tau = 0`——默认关掉，但在需要贴紧生成策略时可以拧开。

旋钮表（`[trainer.loss]`）：

| 旋钮 | 默认 | 作用 |
|---|---|---|
| `eps` | 0.3 | 概率绝对变化超过它，token 被掩码 |
| `adv_tau` | 1.0 | 优势项温度；设 0 = 只剩 KL 正则 |
| `kl_tau` | 0.0 | KL 正则温度；默认关闭 |

## 3. IcePop：MoE 的信任域

`type = "icepop"` 是第二个内置损失，出处是 Ling 团队的 Ring-1T 论文（arXiv:2510.18855，万亿参数 MoE 推理模型的 RL 稳定化方案）：

$$\mathcal{L}(\theta) = -\frac{1}{N}\sum_t \mathbb{1}\left(\alpha \le \frac{\pi(y_t)}{\mu(y_t)} \le \beta\right) \tau_A \hat{A}_t \frac{\pi(y_t)}{\mu(y_t)}$$

区别就在掩码条件：**trainer 到 inference 的重要性比率落在固定带 [0.2, 5.0] 之外的 token 直接丢弃**，且没有单独的 KL 惩罚项。

为什么 MoE 需要更狠的处理？MoE 的路由行为对权重更新极其敏感——训练侧和推理侧的数值路径（kernel、精度、并行切分）本就有微小不一致，dense 模型下这种不一致无害，MoE 下一个 token 路由到不同专家集合，logprob 直接漂移，比率的噪声分布变重尾。IPO 的绝对变化掩码挡不住这种结构性漂移，IcePop 干脆把重尾砍掉。两个信任域的哲学差异：**IPO 信任"努力学习的小概率 token"，IcePop 信任"数值上说得通的 token"**。

## 4. 自定义损失：一个函数的接口

`type = "custom"` 时你提供一个逐序列函数。文档给的例子就是把 PPO-clip 搬进来：

```python
def ppo_clip_loss(inputs: LossInputs, clip_eps: float = 0.2) -> LossOutputs:
    ratio = torch.exp(inputs.trainer_logprobs - inputs.inference_logprobs)
    clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps)
    surr1 = ratio * inputs.advantages
    surr2 = clipped * inputs.advantages
    loss = -torch.min(surr1, surr2)[inputs.loss_mask].sum()
    return LossOutputs(loss=loss, metrics={"clip_frac": ...})
```

`LossInputs` 给了四个流：`trainer_logprobs`（当前策略）、`inference_logprobs`（生成时策略）、`ref_logprobs`（可选，参考模型）、`advantages`，外加 `loss_mask`（这个组件的成员 token）和 `loss_weights`。metrics dict 里的东西自动进训练日志。注意这个接口的形状：**逐序列算、外部聚合**，意味着你写 PPO、REINFORCE 变体、甚至序列级奖励塑形都不用碰 trainer。

## 5. mismatch KL：off-policy 崩溃的体温计

`[trainer.loss]` 之外，trainer 每步都在算一个诊断量：

- **`mismatch_kl/{all,env}/{mean,std,max}`**：当前训练策略和"生成这批 rollout 时"的策略之间的 KL。

它的读法（`docs/training.md`）：

- 稳定的小值：正常的异步错步，健康。
- **持续增长**：off-policy 崩溃的早期预警——策略漂移快过权重同步，重要性修正开始失效。

配套的还有 `entropy/mean`（太低 = 模式塌缩，太高 = 不敢下注）和 `optim/grad_norm`（尖刺先于发散）。这三个量构成 RLVR 训练的"生命体征"，我的实验篇（07 篇）里那次"reward 全消能力"的事故，事后看就是学习率破坏性 + 无信任域监控的组合。

## 6. 信任域的谱系

把三种内置处理方式排在一起，能看到一个谱系：

| 方案 | 出圈 token 的处理 | 出处/立场 |
|---|---|---|
| PPO clip | 对比率裁剪（梯度截断） | 经典，保守但有偏 |
| IPO | 概率绝对变化超 ε → 整个掩码 | prime-rl 默认：绝对变化比比率更符合直觉 |
| IcePop | 比率出带 → 直接丢弃 | Ring-1T：MoE 数值漂移，杀无赦 |

共同点是**逐 token、可解释、有默认值**。没有一个要求你调超参才能跑起来。

## 7. 一句话总结

> RLVR 的稳定性不是调出来的，是裁出来的。看懂一个 RL 损失，先看它怎么对待比率出圈的 token——那是它全部性格的浓缩。
