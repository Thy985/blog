# 研究方法与总结——档案、账本与可带走的东西

> 系列最后一篇回答两个问题：八次实验是怎么被组织成"可审计的证据链"的？以及，把框架篇和实验篇放在一起，哪些东西可以带走？

---

## 1. 研究档案：把实验变成可审计的账本

`research/` 目录不是一个笔记文件夹，是一套**有变异规则的三层结构**：

| 层 | 内容 | 变异规则 |
|---|---|---|
| 原始证据 | `01_raw/` — 所有 run 目录的哈希清单 | **不可变**；靠哈希验证，不靠手 |
| 规范索引 | `00_index/`、`02_experiments/`、`05_process/`、`06_artifacts/` | 每个实验/主张/决策一条规范记录 |
| 叙事 | `04_synthesis/` | 从索引出发论证；引用 ID，不重新推导 |

`03_analysis/`（可再生的派生分析）和 `07_archive/`（被取代的草稿）**不承载任何主张**——一个主张如果只能从草稿里找到，它就不存在。

几个设计决定值得单独说：

- **原始数字不拷贝进档案**。`metrics.jsonl` 留在 `outputs/` 原位（那里被 gitignore，拷贝一份会变成无人能审计的孤儿），`manifest.tsv` 记录每个 run 目录冻结时刻的哈希——run 可以被证明未被改动，但数字永远只有一份。
- **审计一条主张有固定路径**：claim-evidence matrix 里的主张行 → 证据 ID → 实验记录（E0X）→ 配置路径 / 分析脚本 / run 目录 / commit。
- **Episode 赢过一切索引**。实验记录是对 Episode 的索引，不是与它竞争的第二份轨迹；两者冲突时，Episode 赢。这个"每条事实只有一个入口"的规则，终结了早期"两个 writeup 两个数字"的混乱。
- **假设账本与失败账本**。`hypothesis_ledger.md` 记每个假设的出生、修订（第一个假设被修订了五次）、证伪；`failure_ledger.md` 记每次基础设施事故——包括"没跑成"的（E08 的跨模型臂被标记 untested 并附上物理证据：run 目录不存在，见 14 篇）。
- **冻结点**。`research-p8c-final` 不是"最新代码"，是可复现性标记：到这个 commit 为止，一切数字可重建。

八次实验、82 个 commit、176 个 run 目录、n=60 的冻结点——这套组织的成本远低于它避免的重复混乱。

## 2. 假设生死簿

E08 之后，档案里全部假设的最终状态。值得记住的不是右列，而是这个分布本身：**十行里只有两行以"支持"告终**。

| 假设 | 结局 | 死因 / 依据 |
|---|---|---|
| reward 塑形可迁移能力 | 撤回两次 | 产出 E01 的两条门规 |
| 工具可得性是杠杆 | 撤回 | n=1 的 44 分；n=32 反转（E04） |
| H_D 是更好的规划者 | 撤回 | 120 个 planner 轮里 0 次真的写了计划 |
| 蒸馏迁移效应 | 路线被拒 | 0/10 → 0/10（E05） |
| 效应与预算无关 | 证伪 | T=8 反转 −6 分（E05） |
| 门控是机制 | 证伪 | H_P = H_D，H_G 地板（E06） |
| 静态散文承载效应 | 证伪 | H_A-prime 1/16 vs 7/16（E05） |
| 阶段边界时机是维度 | 证伪 | H_REPLAY 17% > H_P 13%，p = 0.77（E08） |
| H_P 是 25% | 过度声明 | n=60 时 13%（E08） |
| 跨模型复制 | **未测试** | 供应商故障，run 目录不存在 |

被杀死的假设几乎都是**最受欢迎的**——"删工具掉分"、"把好轨迹蒸馏下去"、"更聪明的调度器"——直觉恰恰是它们被写进研究问题的原因，也恰恰是它们需要被杀死的原因。

## 3. 八条教训（每条都花掉一次错误结论）

1. **先审计验证器，再声明能力。** 篡改修复 1.000 分 vs 真实修复 0.571 分——对着未审计的 reward 做的任何声明都是仪器的声明（08 篇）。
2. **协议不变量。** 一个序列化、一个验证器版本贯穿训练/推理/评估；比较两个协议的数字就是丢结论（07 篇撤回一）。
3. **先建立非破坏性更新区，再读消融。** 学习率会冒充 reward 说话（07 篇撤回二）。
4. **每条事实一个入口。** 实验记录是 Episode 的索引，不是竞争轨迹；指标修复必须向后传播（12 篇的 WRITE_RE 事故）。
5. **命名之前先复制。** 每个机制主张都诞生于 n=1，每个都被证明错误或过度缩放（10、13、14 篇）。
6. **配对实例，不是配对比率。** 幸存过复制的两个结论都是同实例配对 McNemar；不配对的聚合比较产出了过度声明（14 篇）。
7. **区分基础设施故障与被试故障。** 把供应商宕机误读成模型行为发生了两次；归因前先直接探测端点（09 篇的端点争用、14 篇的跨模型搁置）。
8. **冻结机制，不冻结数字。** 新 commit 改变数字时，writeup 立即标记为被取代，而不是等研究结束。

retrospective 里"哪些做错了"的部分同样值得读：2×2 跑在了欠功效的预算点上（应该先选操作点再设计因子实验，12 篇）；七个单种子臂被写成了 headline（应报种子或报复制，13 篇）；跨模型腿被放任烂掉（应该从第一天就给供应商问题预算时间，14 篇）。

## 4. 框架篇的品味总结

回到 prime-rl 本体，六篇读下来，它最值得学的不是任何一个具体机制，而是三个设计立场：

**立场一：token 是唯一真相。** 推理服务器应该是"简单的 token-only 端点"，模板、解析、loss mask 全部回到客户端可控可测的代码里（renderers，05 篇）；多轮轨迹要么逐字节连续（合并成 O(T) 样本），要么诚实断裂（开新样本），绝不伪造连续性（best-effort interleaving）。

**立场二：算法是数据，不是分支。** trainer 只执行三种 per-token 损失流的和；新算法是 orchestrator 侧的 credit assignment 钩子，永不触碰热路径（03 篇）。好抽象的标志是最复杂的新东西落在系统最安静的地方。

**立场三：偏差要显式管理，不要假装消除。** 完全异步接受 off-policy，代价用 `max_off_policy_steps`（上限）、重要性修正（IPO/IcePop）和 `mismatch_kl`（监控）三件套偿还，且每一件都是可调可观测的一等公民（02、04 篇）。

## 5. 给想跑 RLVR 实验的人：一张检查清单

- [ ] **验证器先审计**：Golden episode + replay 验收，篡改检测进 resolve 定义（08 篇）
- [ ] **一个协议贯穿始终**：序列化、验证器版本、tokenizer，训练/推理/评估共享（07 篇）
- [ ] **先证明更新非破坏**：学习率不毁灭基线能力之前，别读任何消融（07 篇）
- [ ] **操作点先行**：先找到"有信号的预算/难度"，再设计因子实验（12 篇）
- [ ] **组大小 ≥ 8、批次 ≥ 64**：组内无分歧的优势是零（01、06 篇）
- [ ] **盯三个生命体征**：`mismatch_kl` 持续增长 = 崩溃预警；`entropy` 过低 = 模式塌缩；`grad_norm` 尖刺先于发散（04 篇）
- [ ] **单种子数字不进 headline**：要么报种子，要么报复制（13、14 篇）
- [ ] **配对分析优先**：同样的实例上比 A/B，比聚合比率有力得多（14 篇）
- [ ] **负结果记进账本**：被证伪的假设和没跑成的实验都是产出，untested ≠ 失败（14 篇）
- [ ] **一个 run 一个目录、事实一个入口**：可复现性是设计出来的，不是碰运气（15 篇 §1）

## 6. 三种规模，同一个教训

最后一个观察。上游 prime-rl 在千卡集群上训练万亿 MoE，我的实验在一张 4060 上跑 0.6B 的 LoRA——两端差了五个数量级，但实验篇里每次翻车的根因，都能在框架篇里找到对应的防御机制：

| 我的翻车 | prime-rl 的对应防御 |
|---|---|
| 协议 bug 污染评估（07 篇） | renderers 保证 token 逐字节连续；协议不变量（05 篇） |
| 学习率冒充 reward 效应（07 篇） | `mismatch_kl` / entropy / grad_norm 生命体征（04 篇） |
| 篡改修复得满分（08 篇） | 结构化 verdict：`tampered` 字段进 resolve 定义（08 篇） |
| 单种子过度声明（13→14 篇） | trace viewer + per-token 指标：每条 rollout 可回查（02、06 篇） |
| 基础设施故障被误读（09 篇） | `errored_rollouts` > 5% 告警；基础设施与被试分离（06 篇） |

**规模改变的是账本的大小，不改变记账的规则。** 这大概就是这个系列最想留下的一句话。
