# E04：harness 对比——44 分效应与它的反转

> 删掉一个 edit 工具，解 rates 掉了 44 个百分点——这是整个研究的第一条 headline。三天后它在 n=32 上只剩一半是真的：H_B 的大效应扛住了复现，H_C 的单次结果被证明是噪声。E04 的真正产出不是任何一条结论，而是"先复现、再命名"这个流程模板。

---

## 1. 研究问题与假设

- **问题**：删掉一个工具，agent 就不成功了吗——这个效应在真正复现之后还稳定吗？
- **假设 H04**：工具集（action affordance）是杠杆。

## 2. 设计：三个 harness

同一任务集、同一模型、同一验证器，只动 harness：

| 臂 | 配置 |
|---|---|
| **H_A** | bash + edit，自由轮次 |
| **H_B** | 只留 bash（edit 被删） |
| **H_C** | H_A + 完成条件绑定：有未完成的修改时 episode 不许结束 |

每个臂跑 **3 次**，池化到每格 n=32。这个"跑三次"不是起初的设计——它是本篇后半段故事的来源。

一个小的工程纪律也在这里定下：完成条件绑定的配置最初顶着泛化的名字，后来被重命名为它实际配置的那个 harness（提交 `b6c1ad9a8`）——**名字必须指向它真实配置的东西**，否则日志和记录会慢慢积累起一堆名不副实的臂。

## 3. 结果

**第一次 A/B（n=1）**：删掉 edit 工具，解 rates 掉 **44 分**（提交 `d43b15861`）。轨迹挖掘给出了机制（提交 `734496132`）：失败案例**从未尝试过修改**——绑定性的失败是 no-write，不是"改坏了"。也就是说 H_B 的失败模式不是能力不足，是**根本没有动作通道**。

**H_C 初次结果**：完成条件绑定压低了 no-write、抬升了解 rates（提交 `af3bddf12`）。看起来"让 agent 负责到底"是个好主意。

**反转（提交 `6a1177c45`）**：n=32 池化后，**H_C 的效应反了过来**。单次运行的结果是噪声。撤回被作为正式提交记录，且永久生效——那个诱人的单次读数从结论里删除，从撤回表里保留。

**3 次复现后的稳定陈述**（提交 `d732e5ffd`）：**工具支持是效应所在；难度是"任务 × harness"的乘积，不是任务自己的属性。**

## 4. 解释：一对大小效应的不同命运

H_B 和 H_C 走出了完全相反的轨迹，这不是偶然：

- H_B 的效应（−44 分）大到**扛得住噪声**——删掉动作通道是结构性变化，复现多少次都在。
- H_C 的效应小到**和噪声同量级**——单次抽签碰中了，三次池化就现形。

这对组合的价值在于它是一个模板：**大效应验证机制，小效应验证流程**。E04 之后，档案里每个新臂（E06 的 2×2、E07 的七臂）都先复现再命名——"name the claim, then buy the replication"这个习惯从这里定型。

由此排除的东西：

- 任何来自 n=1 运行的工具支持声明。
- "Harness C 改善结果"——n=32 上反转。
- 把难度当作任务单独的属性。

## 5. 局限

H_B 的效应大到不需要运气，H_C 的小效应则需要更多次数才能测准——本文的复现规模恰好够杀死 H_C，不够精确测量它。另外这一切都在实验室阶梯（E03）上，真实 SWE 版本的同一对比是 E05。

## 6. 一句话总结

> 单次运行的 44 分 headline 里，一半是机制，一半是运气——复现不是为了确认，是为了把这两半拆开。
