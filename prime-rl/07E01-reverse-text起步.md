# E01：reverse-text 起步——两个被撤回的结论

> 第一次 RLVR 实验给我的最好礼物不是任何结果，而是两次撤回：一次是协议 bug 污染了"reward 上升且迁移"，一次是学习率冒充了"reward 毁灭能力"。从这两次撤回里提炼的门规，撑起了后面七次实验。

---

## 1. 起点与约束

硬件只有一张 RTX 4060 级别的显卡、11 GB 内存。这意味着：全参数训练免谈（改用 LoRA）、真正的环境交互 RL 免谈（先做离线 GRPO 验证链路）、模型规模上限 0.6B。

任务选了 prime-rl 自带的 `reverse-text`：把短字符串倒序输出，验证器是精确匹配。选它的理由很功利——**信号二元、验证零争议、单轮**，适合当 RL 流水线的调试台。

E01 的问题陈述（研究档案里的原话）：

> 一个能力能否由 reward 塑形、并在一次非破坏性更新后存活——而且测量仪器本身没有悄悄改写答案？

注意最后一个从句，它是整篇的伏笔。

## 2. 设计

- **能力建设**：0.6B 基模型上做 LoRA SFT，建立"会倒序"的初始能力。
- **RL 管线**：单卡离线 GRPO——sampler → verifier → reward → advantage → LoRA 增量，验证整条数据链路能跑通。
- **Reward 消融**：三个变体，V1 = LCS 相似度，V2 = 位置正确率，V3 = LCS + 精确匹配奖励。
- **协议契约**：训练 / 推理 / 评估共享同一序列化和同一验证器版本。

分组：Base（不训）| SFT | GRPO-V1 | GRPO-V2 | GRPO-V3。

## 3. 站得住的部分

SFT 确实建出了能力：**短字符串精确匹配从 0/18 到 7/18**（复核过）。单卡 GRPO 管线端到端跑通——sampler、验证器、奖励、优势、LoRA 增量，每一环都有数据流过。

## 4. 两个被撤回的结论

**撤回一："reward 上升且迁移"。** 最初的对比实验 A/B 显示 reward 曲线上升且 held-out 评估迁移。复核时发现：评估协议和训练协议在边界上有两处细微不同——序列化的细节差导致同一串文本在两侧不是同一串 token。换句话说，**测量仪器在悄悄改写答案**。这个结论被整体撤回，取而代之的是"协议契约"：三种模式（训练/推理/评估）共享一份序列化、一份验证器版本，任何一侧不许单独升级。

**撤回二："每种 reward 都毁灭能力"。** 学习率 1e-4 的 GRPO run 里，模型在倒序任务上的能力肉眼可见地崩掉。我最初把它归因于 reward 塑形（"RL 的梯度把能力冲掉了"）。控制变量重跑才发现：**毁灭能力的是学习率，不是 reward**——把学习率降到非破坏性水平后，同样的 reward 变体不但不毁灭能力，还能温和地塑形。这是把"优化器伪影"误读成"算法性质"的标准案例。

撤回记录在 `tools/swe_lab/PLAN.md` §0 的撤回表里——不是删掉错误结论，是留下尸体并标注死因。

## 5. 产出：两条门规

E01 的最终输出是方法论的，两条规则成为后续所有实验的闸门：

1. **先建立非破坏性更新区，再读任何消融。** 学习率没有通过"不毁灭基线能力"测试之前，reward 消融的读数全是噪声。
2. **协议不变量。** 一个序列化、一个验证器版本，横跨训练、推理、评估。比较两个协议产出的数字，就是丢掉结论的方式——E01 用两次撤回各演示了一遍。

这两条分别流向了 E02（把"先验证测量仪器"升级成整个实验）和 E05（真实 SWE-bench 上坚持协议不变量）。

## 6. 当时不知道、后来才知道的事

E01 还留下一个当时没意识到的局限：离线、单任务族、单模型规模——它完全没有触碰"agent"这个维度。reverse-text 是个完美的调试台，也正是因此它**不产生任何关于智能体行为的证据**。这个空缺直到 E03 才开始填补。

另外，"离线排序/相关性指标能否预测学习"这个问题在 E01 里被排除：离线指标（比如 reward 与正确率的排序相关性）不能预测训练动态。要判断一个 reward 好不好，只能真的训。

## 7. 一句话总结

> 第一次实验的价值不在于答案，在于它逼你承认：在测量仪器被审计之前，你所有的结论都是仪器的结论。

下一篇进入 E02：验证器审计——在第一个 live run 之前，给 reward 装上基准石和重放验收，然后看看审计揪出了什么。
