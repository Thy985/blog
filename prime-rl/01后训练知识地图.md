# 后训练知识地图——SFT、RL 与蒸馏各自教给模型什么

> 预训练给了模型世界，后训练教它做事。三种范式——监督微调、强化学习、蒸馏——本质区别只有一个：**学习信号从哪来，和模型在自己还是别人的轨迹上学习。**

---

## 1. 后训练在流水线里的位置

一个大语言模型的完整生命周期大致是：

```
预训练（万亿 token，下一词预测）
  → 中期训练（退火、长上下文、领域数据）
  → SFT（指令/对话数据，监督学习）
  → RL / 蒸馏（让模型"做得好"而不只是"像样例"）
  → 评估与部署
```

预训练的目标函数是固定的：预测下一个 token。它让模型拥有了能力（capability），但没有让模型**可靠地使用**能力——不会稳定按指令格式输出、不会主动调用工具、不会把推理链走到正确答案上。后训练解决的就是这个"对齐 + 可靠性"问题。

prime-rl 的定位覆盖后训练全部三段：SFT（`uv run sft`）、RL（`uv run rl`）、以及作为 RL 算法变体的蒸馏（`algo.type = "opd"` 等）。这也是为什么它的 README 把自己称为"端到端后训练框架"。

## 2. 三种范式，一张表

把所有后训练方法按两个维度切开——**采样自谁**（模型自己还是别人）和**信号多稠密**（每个 token 还是每条轨迹一个数）——会得到一张非常干净的地图：

| 方法 | 采样自谁 | 学习信号 | 稠密度 |
|---|---|---|---|
| SFT | 教师数据（off-policy） | 交叉熵 | 每 token |
| RL（RLVR） | 策略自己（on-policy） | 奖励（验证器打分） | 每条轨迹 O(1) 比特 |
| On-policy 蒸馏 | 策略自己（on-policy） | reverse KL（教师逐 token 打分） | 每 token |
| Off-policy 蒸馏（= SFT） | 教师（off-policy） | 交叉熵 | 每 token |

这张表的洞察来自 Thinking Machines 的 [On-Policy Distillation 博客](https://thinkingmachines.ai/blog/on-policy-distillation/)：SFT 有稠密信号但 off-policy（学生在教师的上下文里学习，自己犯错时没有矫正机会），RL 是 on-policy 但信号稀疏（一条多步轨迹最后只有一个 0/1）。On-policy 蒸馏是"两全其美"：模型自己走，教师逐 token 告诉它好赖。

他们的数字很能说明问题：数学任务上，Qwen3-8B-Base 从 SFT checkpoint 出发，on-policy 蒸馏约 150 步（7.7 万 prompt）达到 AIME 70%；外推 SFT 需要 200 万 prompt 才到同等水平；RL 路线 Qwen3 报告用了 1.8 万 GPU 小时，蒸馏用约十分之一的成本追平教师水平。

## 3. RL：奖励从哪来

RL 范式下第一个工程问题是：奖励函数是什么？两条路：

- **奖励模型（RM）**：训练一个单独的模型给人味的偏好打分。灵活，但可被 reward hack，且本身是第二个要养的系统。
- **可验证奖励（RLVR, RL with Verifiable Rewards）**：数学有标准答案、代码有测试、格式有正则——奖励由**程序**判定。不可欺骗（前提是验证器写得对），且天然适配"环境"抽象。

prime-rl 走的是 RLVR 路线：奖励来自 [verifiers](https://github.com/PrimeIntellect-ai/verifiers) 环境库——每个环境定义任务集、rollout 协议和 `reward` 函数。环境通过 Environments Hub 分发，训练时每个环境跑在隔离的子进程池里。我的实验篇会反复回到一个教训：**RLVR 的命门在验证器**，一个付了"篡改树"1.000 分的验证器比没有验证器更糟（见 08 篇）。

## 4. GRPO：为什么组相对

有了奖励，第二个问题是：怎么把"这条轨迹得 1 分"变成每个 token 的学习信号？

经典 PPO 的答案是训练一个 critic 网络估计每步的价值，用优势 = 奖励 − 价值。但 LLM 场景下 critic 是和策略一样大的第二个大模型，又贵又难训。

GRPO（DeepSeekMath 提出）的答案更便宜：**同一个 prompt 采一组（group）K 条轨迹，组内基线 = 组平均奖励**，每条轨迹的优势就是自己的奖励减去组均值：

$$\hat{A}_i = s_i - \bar{s}, \quad \bar{s} = \frac{1}{K}\sum_j s_j$$

组均值天然抵消了任务难度（难题全组都低分），不需要 critic。代价是只有当组内**有分歧**（有人成功有人失败）时才有信号——全对或全错的组优势全零。这就是为什么 prime-rl 的经验法则写 `group_size ≥ 8`：组太小，"组内有分歧"的概率太低，很多任务白跑。

GRPO 家族的变体很多，prime-rl 直接内置了几个，每个都对应一个具体缺陷的修复：

| 变体 | 修什么 |
|---|---|
| DR-GRPO（prime-rl 默认优势） | GRPO 除以 std 会让难题的梯度爆炸，去掉 std 归一化 |
| MaxRL | 用组均值替代组 std 归一化，上加权难例，等价于最大似然目标的梯度 |
| RAE（SPIRAL） | 多智能体自博弈里组均值无意义（零和游戏总分恒 0），改用每个 agent 自己的 EMA 基线 |
| Hierarchical GRPO | 提题-解题环境里，解题者只能和同一道题的其他尝试比，提题者只能和其他提题者比 |

这些变体在 prime-rl 里全部实现为 orchestrator 侧的 `score_group` 钩子（03 篇细讲），trainer 完全无感。

## 5. 蒸馏：稠密信号的回归

如果教师模型可用，蒸馏比 RL 便宜得多。两种做法：

- **SFT 蒸馏（off-policy）**：教师生成数据，学生做交叉熵。就是"生成数据集再 SFT"。问题是学生在自己的分布上没有矫正——误差累积，且学到的是教师的**风格**而非判断。
- **On-policy 蒸馏**：学生自己采样，教师对学生的每个 token 打分。损失是逐 token 的 reverse KL（学生分布对教师分布的 KL）作为优势，复用 RL 的整个训练管线。Thinking Machines 的说法是"对 RL 脚本改一行"——把 KL 正则项的参考模型换成教师。

reverse KL 有个重要性质：mode-seeking，学生倾向把概率质量集中在教师的高概率区，且"低 KL 恒对应教师眼中的好行为"，不可通过讨好奖励函数来 hack——因为根本没有奖励函数可 hack。

prime-rl 把这个做成了算法类型 `opd`（teacher 是一个冻结的外部模型端点）和 `opsd`（SDFT：学生以专家示范为条件、以自己为参考做自蒸馏，连教师端点都省了）。

## 6. On-policy 的代价与异步的动机

RL 和 on-policy 蒸馏都要求"信号在模型自己的分布上计算"。但训练器里的参数每步都在变，rollout 是几秒到几分钟前用旧参数生成的——**你永远在训练一个稍微过时的数据分布**。这个偏差用重要性比率修正（离线策略修正），偏差的大小就是 prime-rl 里那个核心监控指标 `mismatch_kl`（04 篇细讲）。

框架设计的分水岭就在这：**同步框架消灭这个偏差**（训完一步、同步权重、再 rollout，严格 on-policy），代价是 rollout 和 trainer 互相等待——对单轮数学题无所谓，对多轮智能体任务（一局 rollout 可能几分钟）吞吐灾难。**异步框架接受这个偏差并控制它**：trainer 和 inference 错开一步流水线重叠，用 staleness 上限和重要性修正兜底。prime-rl 选了后者，且把 staleness 做成一等公民（`max_off_policy_steps`，默认 8）。

这也是本系列框架篇的主线：**异步 RL 的全部工程复杂度，都是在为"接受偏差"买单**——监控偏差、限制偏差、修正偏差。

## 7. 一句话总结

> SFT 教样式，RL 教结果，蒸馏教过程；on-policy 教得准，off-policy 教得便宜。后训练框架的全部设计，就是在"准"和"便宜"之间画一条可调的线。
