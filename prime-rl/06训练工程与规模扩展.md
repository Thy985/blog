# 训练工程与规模扩展——从单卡到千卡的内存账本

> 框架篇的最后一篇看"硬"的部分：FSDP2 分片、专家并行、权重广播、P/D 分离，以及一整套内存杠杆。共同主题只有一个——**大模型 RL 的每 GB 显存都要被指派任务**。

---

## 1. 并行战略：FSDP2 打底，EP/CP 按需开

RL trainer 的并行配置在 `[trainer.model]`，三层：

**FSDP2（默认）**：参数、梯度、优化器状态全分片到数据并行 mesh。旋钮：`dp_replicate`（超大集群上用复制换通信量）、`reshard_after_forward`（默认 true，forward 后重新分片省显存）、`fsdp_cpu_offload` / `optim_cpu_offload`（后者默认开，优化器状态驻 CPU）。

**专家并行 EP**：MoE 的专家权重沿 EP mesh 分片，每层通信量大减。默认 `ep = "auto"`——启动时读模型配置的 `num_experts`，选"能整除专家数、能整除 FSDP island、是 CP 倍数且 ≤8"的最大值。token dispatch 可选 DeepEP kernel（`type = "deepep"`，调 `num_sms`），计算精度独立选（bf16 / deepgemm_fp8 / mxfp8）。

**上下文并行 CP**：单条长序列沿 token 维切开。样式 `ulysses`（head 维分片，吞吐最高，混合 Mamba 模型和 VLM 只支持它）或 `ring`。对 KV 头少的 GQA 模型（如 NemotronH：32 查询头 / 2 KV 头）做 KV 头复制。

只有 custom 模型实现（`model.impl = "custom"`）解锁 EP。`src/prime_rl/trainer/models/` 下是各家族的手写实现——Qwen3 MoE、GLM-4/4.5/5、GPT-OSS、MiniMax M2、DeepSeek-V4、Nemotron-H（混合 Mamba）、Qwen3.5-VL……README 的模型支持表就是按"MoE / EP / CP"三列组织的。

## 2. 内存杠杆清单

`docs/scaling.md` 的 Memory-Tight Recipe 是一份完整的账本，逐项列默认值和代价：

| 杠杆 | 默认 | 省多少 | 代价 |
|---|---|---|---|
| Activation checkpointing（AC） | 开（full） | 大 | 吞吐 ~25% |
| selective AC | 可选 | 中 | 小 |
| AC offloading | 开（`max_inflight_activations=5`） | 峰值显存 30–40% | 吞吐 ~3–5% |
| 优化器状态 CPU offload | 开 | Adam 状态出卡 | 传输时间 |
| full offload + CPU 优化器 | 关 | 梯度+FP32 master+状态全出卡 | 只支持 AdamW/SignSGD，禁梯度裁剪 |
| fused LM head chunking | 1024 token | 免掉 `[batch*seq, vocab]` 的 logits 巨块 | kernel launch 开销 |
| torch.compile | 开 | 碎片整理 | 编译时间 |

两个值得一提的细节：

- **SignSGD**（`optim.type = "sign_sgd"`）：无状态优化器，host RAM 占用减半（8 vs 16 字节/参数——没有动量）。极端显存受限场景（比如 GLM-4.5-Air 两节点训练例子里单节点 sign-SGD trainer + 全量 offload）的救命稻草。
- **fused LM head**：RL 的 loss 需要 per-token logprob，vocab 10 万+ 时 logits 张量是显存大户。自定义 fused kernel 按 chunk 流式算 logprob/entropy，默认 1024 token 一段。

## 3. 权重广播：每一步都在搬家

RL 每步都要把新权重送进推理集群。`transports/weights/` 三个实现对应三档：

- **NCCL**（默认）：同步内存拷贝。SFT 在线 eval 的广播还有个四阶段握手（`.sender_ready` → `.receiver_ready` → `.started` → `.finished`），文件落在 `broadcasts/step_{n}/`——每一步权重转移都可审计。
- **filesystem**：LoRA 场景或无推理服务时回退；外部管理的推理（自己的 k8s pod）自动用它。
- **NIXL**：接收端拉取式 + InfiniBand 直传。每个 NIXL 进程选离自己 GPU 最近的 IB 口；推理 rank 从不同 trainer rank 起拉，流量摊到所有 rail 上。`overlap_transfer_and_replay = true` 开双 arena：一边重放上一组权重一边收下一组。

## 4. 推理侧：router 统治一切

`docs/inference.md` 的部署形状三种，客户端永远只看到一个 URL：

- **single_node**：一个 vLLM engine + 一个 vllm-router
- **multi_node**：多副本（每节点独立 vLLM，`tp/dp` 必须在单节点内放下）或 **wide-EP**（跨节点专家并行，200B+ 模型换 KV cache 空间）
- **disaggregated（P/D 分离）**：prefill 和 decode 分开部署。对智能体工作流这是关键——多轮 rollout 的 prefill 长且重，decode 短而快，混部互相干扰产生长尾延迟

高级项还有 CPU KV cache offload、router replay、llm-d 路由器（`[inference.router]` 可选 llm-d EPP+Envoy）。`examples/advanced/glm-5.3/` 是全家桶：GLM-5 FP8 + P/D 分离 + llm-d router + Mooncake KV offload，README 里的"One-line SLURM deployment"指的就是它。

**自适应并发**（orchestrator 侧）动态调在途 rollout 数，SFT 在线 eval 复用同一控制器（`[eval.concurrency]` 的 `min_inflight/max_inflight`）——推理集群压力成为训练调度的反馈信号。

## 5. 部署：SLURM 模板与 K8s

`[slurm]` 表一加，三个入口全部变 sbatch 提交器——launcher 生成 Jinja2 模板渲染的 sbatch 脚本，把 rendezvous 端点、IP、共享文件系统路径都接好；`--dry-run` 先验证配置再排队（CP 需要 flash-attention 这类校验在 dry-run 快速失败，进了队列才失败就贵了）。

一个容易踩的坑写在文档里：**prime-rl checkout 和 uv venv 必须在共享文件系统上**，且 sbatch 只在 batch 节点跑一次 `uv sync`——node-local venv 会让其他节点的环境是陈旧的。

## 6. 观测体系：异步系统的体检单

`docs/training.md` 的 Important Metrics 一节是我见过整理得最实用的 RL 监控清单，按用途分三类：

**进度**（orchestrator）：`reward/{all,env}/mean` 主信号；`seq_len`、`is_truncated`、`num_turns` 看轨迹形态；`empty_rollouts`、`errored_rollouts` 零星正常、持续 >5% 是味道；`eval/{env}/{avg@k,pass@k}`。

**稳定性**（trainer）：`mismatch_kl`（04 篇详述）、`entropy`、`is_masked`（IPO 信任域掩码比例）、`optim/grad_norm`。

**性能**：`perf/throughput`、`perf/mfu`、`perf/peak_memory`，加上 02 篇说过的互为镜像的 `wait_for_batch` / `wait_for_policy`。

观测默认全走本地文件（`monitors/file/metrics.jsonl`），W&B 和 Prime 平台上传是可选监视器。trainer 和 orchestrator 共享**同一个 W&B run**。指标数量大得刻意（"deliberately logs a large number of metrics"）：每个 rollout 指标都按子集 × 统计量 × 环境三重展开，多环境 run 能发出几千条序列——所以每个 run 自动建一个 `overview` 保存视图，把要紧的指标策展进 train/eval/stability/performance 四栏。

## 7. 经验法则（Rules of Thumb）

文档原话，值钱的是那些数字：

- **Start small**：先在 2 GPU 上把 `examples/basic/reverse-text/rl.toml` 跑通，冒烟干净才谈扩展。
- **batch_size ≥ 64**：更小的批次梯度噪声大，trainer 每步开销主导吞吐。快速消融 128–512，生产 RL 1024+。
- **group_size ≥ 8**：组内无分歧 → 优势全零 → 白跑（01 篇讲过的 GRPO 病）。8 是地板，16–32 常见。
- **Runs never share a directory**：每次启动一个独立 run 目录，想找回或续训就 `--run.name`。
- **`--dry-run` before SLURM**：校验器在 dry-run 快速失败。

checkpoint 侧的实用知识：默认关闭（省盘），`--ckpt.interval 25 --ckpt.keep-last 3` 滚动窗口；续训同命令加 `--resume`；DCP 分片 checkpoint 用 `tools/convert_dcp_to_bf16.py` 导出 HF 格式，`convert_dcp_to_fp8.py` 直接出块状 FP8（vLLM 原生加载）。

## 8. 一句话总结

> 千卡 RL 的工程没有魔法，只有一本被严格记账的预算表：显存分给权重、激活、KV 和优化器，带宽分给 rollout、权重广播和检查点，每项都有默认值和关闭它的理由。
