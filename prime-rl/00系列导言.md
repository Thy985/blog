# 系列导言：从 prime-rl 到异步 RL——一个训练框架和八次实验的完整复盘

> 监督学习教模型模仿，强化学习让模型试错。前一个系列我用 CNN 做分类，这一系列走进后训练的世界：把一个大语言模型从"会说话"训到"会做题、会用工具"，用的框架是 Prime Intellect 的 prime-rl。

---

## 1. 这个系列的由来

前两个系列都在"理解已有系统"：天气分类是理解自己的训练过程，逆向反代是理解一个闭源产品的网络行为。这一系列不同——它关于**训练本身**。

我 fork 了 [Prime Intellect 的 prime-rl](https://github.com/PrimeIntellect-ai/prime-rl)，一个为大规模异步强化学习设计的开源框架。它被用来训练 INTELLECT-3 这样的 MoE 推理模型，宣称能扩展到 1000+ GPU。我的 fork 里有两层东西：

1. **上游框架本体**：`src/prime_rl/` 下 243 个 Python 文件——三进程异步架构、算法抽象、renderers、FSDP2 训练器、vLLM 推理层。这是本系列前半部分（01–06 篇）的解剖对象。
2. **我自己在上面做的实验**：`research/` 目录下 8 个编号实验（E01–E08），每个实验一篇（07–14 篇），从 reverse-text 的 RLVR 起步，到验证器审计，最后落在一个关于"运行时干预如何改变 agent 行为分配"的小研究。这是后半部分的复盘对象。

我的实验环境与上游的目标场景是两个极端：上游瞄准万亿参数 MoE + 千卡集群，我只有一张 RTX 4060 级别的显卡和 11 GB 内存——所以我的实验用 LoRA、0.6B 模型、离线 GRPO。但恰恰是这种落差有意思：**框架的哪些设计在单卡上也成立，哪些是规模专属的，哪些教训与规模无关**。

## 2. 为什么是 prime-rl

后训练框架不少：TRL、OpenRLHF、veRL、NeMo-RL……选 prime-rl 深读有三个原因：

- **异步是第一性设计**。大多数框架把 RL 写成同步循环：rollout → train → 权重同步 → 再 rollout。prime-rl 默认完全异步，trainer 和 inference 永远错开一步重叠运行。对智能体任务（多轮工具调用、长视野）来说，rollout 时间的方差极大，异步不是优化，是必需。
- **算法被抽象成了数据流**。框架的 trainer 不知道 GRPO 是什么——它只消费三种 per-token 损失流（rl / ce / ref_kl）。所有"算法"都退化为 orchestrator 侧的 credit assignment。这是我看过的后训练框架里最干净的算法分层。
- **它对"测量"认真**。run 目录里的 metrics、rollout trace、dashboard、以及它对 off-policy 程度（`mismatch_kl`）的显式监控，都指向同一个认识：RL 实验最大的坑不在训练，在测量。这和我实验里翻过的车完全对得上。

## 4. 阅读约定

- 框架篇（01–06）以源码和官方文档为据，关键设计给到文件路径；实验篇（07–14）以我 fork 里的 `research/` 档案为据，结论都标注证据强度——因为这个系列里**被证伪的假设比被证实的多**。
- 涉及实验的数字（solve rate、p 值、n）全部来自冻结档案 `research-p8c-final`，不做修饰。

## 5. 写作原则

还是那句话：真实项目中最有价值的部分，往往不是配方，而是那些失败、反转和停止信号。这个系列里你会看到：一个被协议 bug 污染的结论、一个在 n=32 上反转的 44 分效应、一个在复制后从 25% 跌到 13% 的 headline。它们和最终幸存的两个小结论一样，都是产出。
