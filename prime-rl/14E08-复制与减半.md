# E08：复制 n=60——headline 的葬礼与遗产

> 这是档案里最重要的实验，而它是一个"负结果"。4 臂 × 3 种子 × 20 任务的复制把 H_P 的 25% 砍到 13%（种子 1 重跑 0/20），杀死了"阶段边界时机"这个维度，却让两个配对 McNemar 检验幸存（p = 0.031、p = 0.008）。幸存的陈述比 headline 小了一半——这是复制的预期结果，不是失败。

---

## 1. 研究问题与假设

E07 的七个臂全是单种子 n=20（13 篇）。本篇的问题只有一个：

> **哪些单种子结论能在复制中幸存，哪些是种子伪影？**

- **H15**（阶段边界时机是维度）——**被拒**。
- **H16**（banner 效应在复制中存活）——**部分被拒**：存活的是方向，不是尺寸。
- **H17**（横幅改变动作分配而非推理或努力）——**成立**。
- **H18**（效应跨模型复制）——**未测试，被基础设施卡死**。

## 2. 设计：三个阶段

**Phase 8A — 跨模型复制（未完成）**：bunny 臂和 DeepSeek-v4-flash 臂的配置全部写好、端点可通、smoke 通过——但正式 run 始终没有发出。bunny 卡在 aarch64 上的 `deep-ep` 元数据问题，修了一次（提交 `6315a6e06`）后被放弃；DeepSeek 臂从未运行。**物理证据**：`rl-8-bunny-*` 和 `rl-8-deeps-*` 的 run 目录根本不存在，只有 smoke 目录在。

档案的处置方式值得单独学：H18 被标记为 **untested**，不是 failed，并附上目录级证据。**没跑成的实验不是失败，是未测试**——这两个词的区别就是档案和笔记本的区别。

**Phase 8B — H_REPLAY 臂**：一个聪明的新设计——第 1/3/5 轮各注入一次，注入总量与 H_P 相同但**脱离阶段边界**。如果"边界时机"真承重，H_REPLAY 应显著低于 H_P。这是专门为杀死 H15 造的臂。

**Phase 8C — 复制本体**：4 臂（H_A / H_ONCE / H_P / H_REPLAY）× 3 种子 × 20 任务 = **每臂 n=60**，然后逐实例配对分析 + 轨迹中介链。

## 3. 结果

**逐种子解 rates**：

| 臂 | 种子 0（E07 run） | 种子 1 | 种子 2 | n=60 |
|---|---|---|---|---|
| H_A | 0% | 10.5% | 10.5% | **7%** |
| H_ONCE | 5% | 0% | 5.9% | **3%** |
| H_P | **25%** | **0%** | 15% | **13%** |
| H_REPLAY | 15.8% | 21.1% | 15% | **17%** |

三件事同时发生：

1. **H_P 的 25% 是单种子噪声。** 种子 1 重跑 0/20。E07 的 headline 腰斩——而且注意 H_A 也一样：种子 0 的 0% 低估了它的真实水平（7%）。
2. **H_REPLAY 17% > H_P 13%，p = 0.77。** 阶段边界时机**不是**维度——H15 死亡。"何时说"不重要，"说多少次"才重要。
3. **两个结论幸存，都是配对 McNemar**（同样的 20 个实例上配对）：
   - **有横幅 vs 无横幅：p = 0.031**（单侧）；
   - **多次注入 vs 单次注入：p = 0.008**。

**幸存者的共性**：都配对在实例上。不配对的聚合比较（"17% vs 13%"这种独立样本差）在这个 n 下毫无统计力——**产生过度声明的正是它们，产生幸存者的正是配对**。"Pair on instances, not on rates"从这次实验起成为档案的第 6 条教训。

## 4. 中介链：机制的终局

n=60 上的轨迹中介链（提交 `b257519fe`）：

| 量 | 读数 | 含义 |
|---|---|---|
| 状态改变动作占比 | 0.04 → 0.07（仅解出的 episode：0.17 → 0.30） | 动作分配移动 |
| 总工具调用数 | **持平** | 不是更努力 |
| 首次编辑时间 | **没有更早** | 不是更早行动 |
| 最长连续侦察 | 变短 | 冗余侦察减少 |

agent 没有做更多的事，也没有更早开始改——它把**同样数量的动作重新分配**向状态改变调用。加上贯穿全部 32+60 个 episode 的"0 次测试运行"，推理假说、努力假说、时机假说全部出局。

**最终幸存的陈述**（主张矩阵的措辞，一字未动）：

> 逐轮在 user 角色注入阶段上下文，会改变 agent 的动作分配方式，且在受测预算下改善结果。它不改变推理，不增加交互努力，不使 agent 更早行动，也不使它学会验证。

final_report 给这句话的定位是"本研究所能支持的天花板"——比 E07 的 headline 小一半，但每一个字都有 p 值和配对数据垫底。

## 5. 证据强度表

| 主张 | 证据 | 强度 |
|---|---|---|
| 有横幅改善解 rates | E08，McNemar p = 0.031，配对 n=60 | **强** |
| 多次注入优于单次 | E08，p = 0.008，配对 n=60 | **强** |
| 门控不是机制 | E06，H_P = H_D，H_G 地板 | **强** |
| 静态散文不是机制 | E05，H_A-prime 1/16 | **强（负）** |
| 效应受预算塑形 | E05，T=4 +32 → T=8 −6 | 中 |
| 动作分配中介 | E08，观察性链条 | 中 |
| 角色对比（system ≠ user） | E07，单种子 n=20 | 弱 |
| 跨模型复制 | — | **无证据（untested）** |

这张表的形状本身就是结论：**最强的两行恰好是唯一做了配对复制的两行。**

## 6. 局限

n=60 仍是 20 任务 × 3 种子，13% vs 7% 的差距检验力很薄（p 值靠配对而非独立样本撑着）；中介链是观察性的（同一批轨迹既测中介又测结果，非受控估计）；两个仓库 20 实例无分层；跨模型至今悬置。

## 7. 一句话总结

> 复制不是给结论盖章，是给结论称重——E07 称出 25%，E08 称出 13%，真实的是后者。一份研究档案最珍贵的页面，往往就是那页写着"我们的 headline 被腰斩了，以下两个小结论幸存"的页面。
