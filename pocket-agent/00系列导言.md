# 系列导言：把编程 Agent 装进口袋

> 编程 agent 已经成了很多人桌面上最强的生产力工具，但它被拴在电脑上。手机是随身携带时间最长的计算机——这一系列回答一个问题：**能不能把编程 agent 装进口袋？** 答案不止一个，而是一整个开源生态。

---

## 1. 问题的起源

2026 年，编程 agent（Claude Code 一类）的形态已经稳定：一个跑在终端里的 Node.js 进程，围着大模型 API 转工具环——读写文件、执行命令、跑测试、提交代码。它有两个硬约束：**需要 Node 运行时**，**假设它跑在 glibc Linux/macOS/Windows 上**。

于是"在手机上用它"成了一道系统题，三类解法对应三个家族：

- **本机派**：把 agent 运行时整个塞进手机。Termux 是社区惯例，[DSHA](https://github.com/DSH-APP/DSHA) 内置 proot Ubuntu，我自己的项目[星渡](https://github.com/Thy985/xingdu-dsh-android)（xingdu-dsh-android）走 Bionic Node 直跑；
- **远控派**：agent 留在 PC/服务器，手机只是壳。我对 [ZCode](https://github.com/Thy985/ZCode) 官方安卓壳的改造是一例，DSH 社区的 dsh-Remote 家族是另一片森林；
- **操机派**：手机不是运行环境也不是终端，而是 agent 的**身体**——Mobile-Agent、UI-TARS、AutoGLM 这一类。

三个家族不是互斥的：DSHA 同时做了本机运行时和设备桥，"手机就是 agent 的手"；ZCode 仓库里还有反向操作（agent 控制安卓模拟器开发，14 篇）。

## 2. 两个自研项目：一对镜像

本系列的两个"项目锚点"恰好站在同一条分界线的两侧：

- **星渡**（xingdu-dsh-android）：把 DeepSeek Harness（DSH）的完整运行时——Bionic 版 Node.js 24、bash、ripgrep、自研 PTY 助手——打进 825MB 的安卓应用，前台服务本机跑 `dsh web`，免 ROOT 免 Termux。**它回答"怎么让 agent 真的在手机里"**；
- **ZCode fork**：官方安卓壳只是远控页的 WebView，这个单提交 fork 把它补成日常可用的客户端——多后端信任、附件、移动适配。**它回答"怎么让手机安全地够到 PC 上的 agent"**，并明确写下反面理由："上游 server 依赖 node-pty、ssh2 等原生模块并锁定 Node 24，Android 上直跑不现实"。

一个把复杂度搬进手机，一个把复杂度留在桌面——同一道题的两个相反答案，各自有一套完整的安全模型。

## 3. 生态全景：三个家族与一张三层栈

### 3.1 本机派：四方案谱系

| 方案 | 环境形态 | 包体 | 兼容性 |
|---|---|---|---|
| **Termux** | 用户手动装 Node/工具链 | 按需 | 自建编译仓库 + proot-distro |
| **DSHA** | 内置 proot Ubuntu（glibc） | 278MB | apt 全套，上游插件不改 |
| **星渡** | Bionic Node 直跑（无发行版层） | ~825MB | 借 Termux 编译成果 + 逐依赖补丁 |
| **DSH Mobile** | 精简 bionic 闭包 | 70MB | 精选依赖（[Soodok](https://github.com/Soodok/Deepseek-Harness-Local-Android)，星渡的 runtime reference） |

谱系两端是两种哲学：**兼容性换包体**（DSHA）vs **性能换工程量**（星渡）。官方[讨论区](https://github.com/deepseek-ai/deepseek-harness/discussions/6865)还记载了更多变体（Shizuku 免 root 方案、100KB Termux 补丁层、[dsh-work](https://github.com/shenjingnan/dsh-work)、[Kuikly 跨端客户端 + botbus-protocol](https://github.com/botbus-io/botbus-protocol)）。

### 3.2 远控派：一个三层栈

远控派内部不是一个方案，是**三个可独立替换的层**——这是理解 15+ 个项目的唯一正确方式：

```
UI 层      原生 App │ Web 完整版（PWA） │ 桌面反代 │ 桥接 │ IM 机器人
通道层     局域网 │ Tailscale │ SSH 反向 │ Cloudflare（临时/Named）│ frp │ cpolar
安全层     配对与认证 │ 边界代理（重写 Host/Origin）│ API 网关白名单 │ 熔断
```

UI 层代表：[dsh-Remote](https://github.com/Blank-not-black)（+ [produce123 深改分支](https://github.com/produce123/dsh-Remote-mod)）、Hyna-hla（审批横幅）、saya-ch/dsh-mobile（多通道 + `/mobile` 定制）、dsh-mobile-web（PWA 完整聊天）、66jiujiu99（桌面反代）、dsh-roam（扫码续接）。通道层：Guuu16（SSH 反向自动化）、dsh-phone-access（CGNAT 自愈）、dsh-web-remote-frp。安全层：StyleJeke/dsh-tunnel-plugin（边界代理）、bluelightgit/dsh-remote-access（API 网关白名单）、dsh-remote-mobile（认证纵深）、dsh-webgate、dsh-bridge（IM 矩阵）。三层各占 08/09/10 篇。

### 3.3 操机派与反向家族

操机派（14 篇）：手机是被 agent 操纵的身体——[AppAgent](https://appagent-official.github.io)（腾讯）、Mobile-Agent（X-PLUG）、UI-TARS（字节）、AutoGLM（智谱）、[DroidRun](https://github.com/droidrun/mobilerun)、AndroidWorld 类基准。DSHA 的设备桥（06 篇）是它与编程 agent 的杂交地带。反向家族（14 篇）：agent 坐在桌面控制安卓模拟器开发——ZCode 的 `android-emulator-plugin`，与本系列互为镜像。

## 5. 阅读约定

- **比例**：知识约 60%，项目约 40%。案例篇（03–06、11）以项目为主，其余各篇以知识为主、项目做锚点；
- **证据分级**：星渡、ZCode fork、DSHA 的结论以**克隆仓库源码**为据（关键断言给到 file:line 或类名）；远控生态项目（08–10 篇）以 README 与**代表性项目的源码**（StyleJeke/dsh-tunnel-plugin、bluelightgit/dsh-remote-access 已克隆走读）为据，其余标注"文档口径"；
- **快照**：2026-10-24；安全结论区分"文档承诺 / 代码可验证 / 未经独立审计"三档；
- **演进注记**：项目技术路线不预设正确，凡有转折如实记录。

## 6. 写作原则

还是那句话：真实项目中最有价值的部分，往往不是配方，而是那些失败、反转和停止信号。这个系列里你会看到：一个为了通过 403 而被迫发明"同时重写 Host 和 Origin"的边界代理、一段为了绕开 resize NaN 而放弃壳层方案的论证、一张"不能推导的保证"安全表、一个至今待修的权限缺口。它们和 10/10 的验收一样，都是产出。
