# 总结——决策表、三种文化与可迁移清单

> 系列收官。三件事收拢：一张从场景到方案的决策表；这个生态里反复出现的三种工程文化；以及一张可迁移清单。

---

## 1. 第一问：agent 应该在哪

三个候选位置，判定条件其实很短：

| 你的情形 | 答案 | 家族 | 详读 |
|---|---|---|---|
| 写代码的主战场在 PC，手机只是"顺手看看/批个准" | agent 留在 PC，手机当壳 | **远控派** | 08–10 篇 |
| 手机就是你的唯一电脑（无 PC/长期外出） | agent 上手机 | **本机派** | 02–07 篇 |
| 要 agent 替你操作手机 App | 手机是被操作对象 | **操机派** | 13 篇 |
| 你在开发安卓应用，想让 agent 干构建调试的活 | agent 桌面 + 模拟器工具箱 | **反向** | 14 篇 |

四条路可以并存——DSHA 同时占前三个位置就是证明。

## 2. 本机派四方案选型

| 维度 | Termux | DSHA | 星渡 | Soodok DSH Mobile |
|---|---|---|---|---|
| 上手门槛 | **高**（命令行全手动） | 低（装 APK） | 低（装 APK） | 低 |
| 兼容性 | apt 全套（自建仓库） | **apt 全套**（proot） | 借 Termux 成果 + 补丁 | 精选闭包 |
| 性能 | 好（Bionic 原生） | proot 翻译开销 | **原生直跑** | 原生 |
| 包体/占用 | 按需 | 278MB | ~825MB | **70MB** |
| 设备能力 | Termux:API | **内置设备桥** | 无（截图默认保护） | 无 |
| 数据安全 | 自己管 | 备份体系最全（79 类） | SAF 快照导出 | — |
| 适合谁 | 折腾党/已有 Termux 资产 | "要全能，不想折腾" | "要原生速度，接受边界" | 极简设备 |

一句话分诊：**怕麻烦选 DSHA，要快选星渡，什么都想要选 DSHA + 忍 proot，设备很旧/存储小选 Soodok**。

## 3. 远控派三层选型

**UI 层**：要审批横幅/通知常驻 → 原生 App（Hyna-hla 一类）；不想装 App → dsh-mobile-web（PWA）；只要"PC 界面在手机上"且接受原生宿主功能失效 → 桌面反代（66jiujiu99）；要最广通道 + 对话里定制手机端 → saya-ch/dsh-mobile。

**通道层**：有 VPS + 延迟敏感 → SSH 反向（Guuu16）；要固定公网 → Cloudflare Named Tunnel 或 frp；CGNAT + 不想养服务器 → Tailscale 或 dsh-phone-access；纯应急 → 临时隧道。

**安全层**：纯局域网 → token（fail-closed 语义优先）；要公网 → **必须**过边界代理网关（10 篇三道门原理），认证纵深与 API 白名单二选一起步、二者皆有更稳。永远记住：**通道不等于身份，明文隧道 + 无认证 = 把 agent 的 shell 交给路人**。

**场景组合速查**：

| 场景 | 推荐组合 | 代价标注 |
|---|---|---|
| 出差时在酒店用手机盯 PC 上的 agent | 原生 App（审批通知）+ Tailscale + 网关（可选公网） | 两端都要装 Tailscale |
| 手机是唯一电脑 | DSHA（兼容性最全） | proot 开销 + Android 11+ |
| 极客式全控 | Termux + 自建（或 DSHA 的 proroot 实验） | 时间成本最高 |
| 低配旧手机 | Soodok 精简闭包 | 功能面窄 |
| agent 帮我操作手机 App | DSHA 设备桥（结构化、可审计） | 能力上限锁死在桥端点 |
| 安卓开发自动化 | 反向：android-emulator-plugin（MCP） | 模拟器 ≠ 真机 |
| 在 IM 里派任务 | dsh-bridge 的机器人矩阵 | IM 通道的凭据管理要认真 |

**两个自研项目的选型复盘**（验证决策逻辑的自洽性）：星渡选本机派 Bionic 路线——目标"免 Termux 免 ROOT 原生直跑"，愿付补丁族维护 + targetSdk 窗口 + 825MB 代价，且主动放弃设备能力（截图默认保护），用户画像是"把手机当便携工作台的 DSH 用户"——自洽；ZCode fork 选远控派——上游依赖结构（node-pty/ssh2/锁 Node 24）使本机化成本失控，把工程力气花在端点信任与移动适配——自洽。**选型不是终身制，但切换要按同一清单重新验证**（星渡 ROADMAP 原话）。

## 4. 三层知识地图

```
运行时层（02–07）  "agent 怎么在手机里"
  W^X 与 exec 边界 → Bionic vs glibc → 三条路线（proot / 借 Termux 编译成果 / Termux 自建）
  → PTY 桥协议（fd-3 控制通道、pidfile 决策）→ 装机流水线 → canary 式受管更新 → 备份 → 发布渠道经济学

远控栈（08–12）    "手机怎么够到 agent"
  UI 层（原生 App / Web 完整版 / 桌面反代 / IM 机器人）
  × 通道层（LAN / Tailscale / SSH 反向 / Cloudflare / frp）
  × 安全层（边界代理重写 Host/Origin 铸 cookie / 具名方法白名单 / 认证纵深 / 熔断）
  → "通道不等于身份"、"反代只搬界面不搬能力"、"同一 runtime 不是第二个视图"

能力层（13–14）    "谁操作谁"
  操机派（结构化无障碍 vs 视觉端到端）× 编程 agent（审批文化/验证器传统）
  → DSHA 设备桥的杂交 → 反向：agent 管安卓（MCP 工具设计三通则）
```

系列开头的问题——"能不能把编程 agent 装进口袋"——的完整答案是：**能，且有三条成本结构完全不同的路；选哪条不取决于技术优劣，取决于你的依赖结构（上游锁了什么）和使用重心（你在哪台设备上干活）**。

## 5. 三种工程文化

跨越 25+ 个个人项目，三种文化反复出现，也是项目质量的真实分层线：

**文化一：边界即文档。** 最优秀的项目都把"不能做什么"写成一等公民：星渡 README 第一屏声明"不是实时挂载或双向同步"；DSHA 的安全模型每条信任边界配一列"**不能推导的保证**"；66jiujiu99 把"反代只搬界面不搬能力"写成天花板声明；bluelightgit 标注"Tunnel-only 是匿名传输，不提供身份认证"；StyleJeke 的"插件不提供全链路 TLS"。**安全承诺的可信度与"敢写没做到"的数量成正比**——这是本博客四个系列共同的第四变奏。

**文化二：边界不变量先于功能。** 星渡 ROADMAP 把"不绕过审批、不加无约束 shell、不放宽 WebView 与 URL 策略"写进不变量区；ZCode fork 每个改动以"保留原有安全模型的前提下"为前提。技术路线可以错、可以改，**但安全不变量不随路线漂移**。

**文化三：实测教训比设计文档贵。** StyleJeke 的三条注释（"回环 Host + 外部 Origin 实测同样是 403"、"cloudflared 会把 Host 改写成源站地址"、"Origin: null 是合法请求"）没有一条能从文档推导——全是流量级别的撞坑。加上星渡的验证状态表、DSHA 的缺口生命周期，本系列的证据分级（实测 > 源码 > 文档）就是从这些项目身上学来的。

## 6. 可迁移清单

- [ ] **搬运前先解剖依赖结构**：纯 JS 内核好搬，原生模块（pty/ssh）和 glibc 假设是墙——先列清单再选路线（01 篇）
- [ ] **运行时三选一**：proot 换兼容、借成熟 Bionic 发行（Termux）换速度、自建换自由——选择变量是"上游变化速度"（02、03 篇）
- [ ] **补丁族三纪律**：挂 issue、单一真源、与上游解耦可重放（03 篇）
- [ ] **PTY 桥的数据与控制分离**：字节流走 stdio，控制走独立 fd + 行协议；同步读 pid 用 pidfile 不用管道（03 篇）
- [ ] **自更新用 canary**：隔离区真实启动 → 验证 → 原子切换 → 失败回切；区分"挂了"和"慢"（05 篇）
- [ ] **适配层贴官方公共契约**，不碰私有内部；上游已适配的部分不重复加工（04、11 篇）
- [ ] **安全判定类型化**：输出不是布尔，是 Pinned/NeedsTrust/Invalid 这样的处置类型（06、11、12 篇）
- [ ] **未知即拒绝（fail-closed）**，但按"用户能否理解未知物"分档：设备命令硬拒、URL 来源可确认（06、12 篇）
- [ ] **安全决策落成可单测的纯策略类**——8 行的 ZipPathPolicy 守住 825MB 的解压（04 篇）
- [ ] **通道与身份解耦**；给自己的服务做公网发布时，边界代理的"Host/Origin 双写 + cookie 铸造"不是可选项（10 篇）
- [ ] **白名单到方法名粒度**，匿名通道只读子集，解析失败即空串（10 篇）
- [ ] **有状态资源的工具设计三通则**：查询与变更分离、前置检查显式化、工作流知识与原子能力分层（14 篇）

## 7. 生态的下一步

三个值得盯的方向（不做预测，只列变量）：操机派与本机派的合流（DSHA 已示范，审批将成为瓶颈设计点）；远控栈的产品化收敛（动物园会不会长出官方整装方案，ZCode relay 已是雏形）；**本地小模型**——星渡 README 原话"本机引擎不等于离线模型"，这条最后的依赖如果消失，隐私边界将被重画。

## 8. 收束

五个系列的第五个结尾，还是那句话的第五次变奏：真实项目中最有价值的部分，不是配方，是诚实——这个生态里最动人的不是 25 个项目各自的功能，而是它们共同遵守的默契：**把能做什么写在第一屏，把没验证什么写进验证状态，把做不到什么写进"不能推导的保证"**。

技术会过时（targetSdk 窗口会关、渠道规则会变、模型会更替），但这份诚实是所有这些项目真正共享的运行时。
