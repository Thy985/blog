# 远控 UI 层——原生 App、Web 完整版与桌面反代

> 远控派的第一层是 UI：手机上呈现什么。这个层聚集了 DSH 生态最多的项目，因为它是分歧最大的一层——"手机上该看到什么"有三种互不相让的答案。本章把三种哲学并排拆开，每种都看它最诚实的限制。

---

## 1. 三种哲学

| 哲学 | 代表 | 一句话 |
|---|---|---|
| **原生 App** | dsh-Remote 家族、Hyna-hla、saya-ch/dsh-mobile | 手机就该有手机的体验 |
| **Web 完整版** | dsh-mobile-web（掌上 dsh） | 浏览器里做一个真正的移动聊天 UI |
| **桌面反代** | 66jiujiu99/dsh-plugin-remote-mobile | 什么都不重做，把 PC 的界面搬过来 |

（ZCode 官方安卓壳是第四种：桌面 UI 直接塞 WebView——11 篇作为案例单独讲。）

## 2. 原生 App 家族

这个家族内部已演化出清晰的分工：

- **dsh-Remote（原版，Blank-not-black 维护）**：DSH 插件 + 独立网关 + Android App/WebUI 三件套；局域网/Tailscale 直连，多服务器自动测速择优，聊天记录可离线查看，Token 鉴权。生态里"标准件"式的存在；
- **produce123/dsh-Remote-mod**：深度魔改分支的治理样本——**移除原版文件传输、改用 Syncthing**（大文件走成熟同步工具），增加实时推理显示、工作区直接读取，且**可与原版共存**。"分叉不背刺上游"的教科书做法；
- **Hyna-hla/dsh-remote**：找到原生 App 的**不可替代场景**——审批。需要审批或问答确认时，手机端收**高优先级横幅通知**；前台服务常驻，任务完成自动提醒；UI 对齐桌面端风格，内置 5 套主题。"连接方式的选择权留给用户"；
- **SCSpotato/dsh-remote**：服务端插件暴露 `/remote/*` 路由，补文件操作能力（列目录、上传下载、删除重命名）——"两端协同"形态；
- **mrRisega/dsh-remote**：卖点收敛到一条——"安装即得专属加密地址"，无需同一 WiFi、无需公网 IP 与内网穿透；
- **saya-ch/dsh-mobile**：集成度最深的样本。远程通道选项最全（局域网、Tailscale Funnel、cpolar、cloudflared、自建 FRP、自有反向代理）；独特能力是**在 DSH 对话里用 `/mobile` 命令定制手机端**，改文件后手机页面通常自动刷新——用 agent 自己改造自己的遥控器。安全侧分层：移动访问独立 HTTPS 与设备配对，App 固定局域网私有 CA，公开远程通道用系统信任的证书——**私有 CA 只在局域网信，公网只信系统 CA**。

原生家族的共同结论：**审批通知是原生 App 的护城河**（横幅、前台服务、震动叫醒是 Web/反代给不了的），其余功能 Web 方案都能逼近。

## 3. Web 完整版：dsh-mobile-web

"掌上 dsh"走"浏览器里做个真 App"路线：6 位码配对、设备信任、SSE 实时流式对话、思考过程折叠、工具调用卡片、审批与提问应答、文件上传（24MB 上限）、**PWA 常驻**（添加到主屏幕，像 App 一样打开）。

它最有价值的一条是**反向的诚实**："明确要求公网访问务必套 HTTPS 反代，不要把明文端口直接暴露"——Web 方案天然亲和"通道层不设防"的滥用，把这句话写进 README 是把安全边界前置到 UI 层文档（10 篇的三道门是它的技术版）。

## 4. 桌面反代：只搬界面，不搬能力

66jiujiu99/dsh-plugin-remote-mobile 是反代路线的标本：把 PC 上完整的 DSH Web UI 反代到 `http://<LAN-IP>:17890/m`。优势干脆：**零第三方依赖，DSH 加什么新功能，手机上就有**。

但它的 README 写下了这条路线的天花板（原话要义）：

> 反代只搬"界面"，不搬"能力"。会话、消息、审批、插件设置等**纯网络请求**可用；但**依赖 Electron 的功能**（如 Agent 浏览器 webview、原生目录选择对话框）在手机上会显示正常但**点击失败**。

"显示正常但点击失败"是反代路线最隐蔽的坑：UI 存在 ≠ 能力存在。判断标准一句话——**凡是 PC 上靠原生宿主（Electron/浏览器扩展/本地对话框）实现的功能，反代后都是死的**。

## 5. 桥接：dsh-roam 的中间道路

dsh-roam 在浏览器与原生 App 之间架桥：不装 App 也能用手机浏览器**扫码续接会话**；装了 AI-HUB App 则可用同一地址、同一 6 位配对码接入原生 App。公网支持 Cloudflare 临时隧道或自有固定域名 + frpc（Let's Encrypt 自动续期）。定位原话："官方 DSH 的**本地优先移动接入层**"——手机端只提供会话操作，设置、插件、终端、文件管理仍然留在电脑上。这个"接入层"的克制：**承认手机场景只需要一个子集**（会话、审批、查看），其余留原地。

## 6. 三种哲学的对照表

| 维度 | 原生 App | Web 完整版 | 桌面反代 |
|---|---|---|---|
| 功能覆盖 | 按需实现 | 按需实现 | **自动跟上游**（含死功能） |
| 审批体验 | **横幅/通知最优** | 页面内 | 页面内 |
| 维护成本 | 高（跟 DSH 版本） | 中 | **最低** |
| 原生宿主功能 | 可自建 | 部分可自建 | **不可用** |
| 门槛 | 装 APK | 开浏览器 | 开浏览器 |

## 7. 边界与不足

本章项目均为社区个人维护，star/活跃度与最新版本未逐一审计；dsh-Remote 家族各分支间的功能矩阵以 README 自述为准；saya-ch 的 `/mobile` 定制能力依赖 DSH 对话内插件机制，上游变更可能影响；66jiujiu99 的"死功能清单"会随 DSH 版本漂移。

## 8. 一句话总结

> UI 层的三种哲学对应三种诚实：原生 App 诚实于"手机需要手机的交互"，反代诚实于"我不重做任何东西"，而两者的交界处横着那句话——反代只搬界面，不搬能力。
